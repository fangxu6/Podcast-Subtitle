# 第165期 赛博国际主义

- SRT 条目：1975

## 内容摘要

本期先讨论近期大模型更新，重点是 Claude 4、DeepSeek R1-0528 以及模型蒸馏。节目认为 R1-0528 虽然只是后训练层面的渐进式更新，却显著提高了思考、编程和多语言能力；通过蒸馏把大模型能力传给小模型，也可能让开源模型在本地设备和手机上获得更大的实用价值。随后话题转向特朗普政府对哈佛大学、外国留学生和中国理工科学生的限制，讨论行政命令、司法拉锯、国际学术合作和个人选择受到的影响。

节目中段以《地狱潜兵 2》的“赛博淞沪会战”为例，讨论来自不同国家的玩家如何因为共同目标协作，游戏如何在低门槛的共同体验中消解现实宣传带来的偏见。接着回顾 Java 三十年，认为 Java 语言本身有表达力不足和模板代码繁多的问题，但 JVM、字节码和分层架构深刻影响了后来的编程语言、Android、LLVM 和 WebAssembly。

最后评议蚂蚁团队发布的开源 AI 技术版图报告。节目认可它用 OpenRank、分类和时间序列把快速变化的开源生态呈现出来，但提醒应用开发框架、Agent 框架和开发工具仍处在混战期，不能仅凭活跃度数据宣布某个方向已经衰落。报告若要长期有价值，需要分层、持续维护、建立领域评价标准，并同时区分“有多少人关注”和“判断是否正确”。

## 时间线

### 00:00-14:23：DeepSeek R1-0528 与大模型竞争

- Claude 4 的发布在综合评价上没有形成强烈反响，尤其与编程 Agent 配合时并没有稳定超越上一代；节目认为 Anthropic 还要面对高成本和必须赚钱的压力，而 Google、DeepSeek 等公司可以用更低价格或开源方式竞争。
- DeepSeek R1-0528 没有更换核心架构，主要通过后训练优化，却让第三方 Intelligence Index 的分数从约 60 分提高到 68 分，接近当时最高的模型水平。节目把这种实质性进步仍称作小版本，视为 DeepSeek 技术导向和克制宣传风格的体现。
- 实际使用中，R1-0528 的平均思考时间和思考内容明显增加，但仍会根据内部奖励标准在较快得到答案时提前停止；编程任务更容易直达主题，成功率和完成速度也有所改善。
- 模型会更多跟随提问者的语言进行思考，中文、英文以及西班牙语、法语的表现变化，被节目视为多语言训练和语料改进的信号。架构不变也可能意味着 DeepSeek 正在为更大的 R2 版本积累准备。
- DeepSeek 还用 R1-0528 蒸馏千问 3 的 8B 模型，报告了约 10% 的基准提升。节目进一步设想，如果把这种能力蒸馏到激活参数较少的 Qwen3 30B-A3B 或面向手机的 2B、4B 模型，本地快速推理的质量和普及度都可能明显提高。

### 14:23-32:16：哈佛、留学生与美国学术合作限制

- 节目先解释哈佛大学在美国高等教育中的特殊地位：历史悠久、资源和校友影响力巨大，尤其在法律和政治领域拥有超出普通大学的影响。特朗普政府撤销经费、指责其政治偏见并限制其招收外国学生和开展国际科研合作，因而不仅是普通的大学政策争议。
- 哈佛通过债券等方式抵消部分联邦资金减少，相关措施又遭遇诉讼和暂缓执行。与此同时，美国暂停全球留学签证面谈并计划加强社交媒体审查，针对中国学生的签证限制还可能波及芯片、计算机、AI、生物等关键领域。
- 节目认为，政策背后既有特朗普打击民主党和中国的个人及政治动机，也有国务卿等强硬派借机推动意识形态政策的因素；对哈佛的具体打击还被讨论为与美国国内对以色列、犹太社群和校园抗议的矛盾有关，这些判断仍属于节目分析而非确定结论。
- 法院相互推翻或暂缓行政措施，市场却没有因此恢复信心。节目据此担忧，关税和签证政策造成的供应链、人才与信用损失可能已经难以完全逆转，司法和政治纠错也只能带来拉锯。
- 对普通留学生而言，影响不是抽象的国际关系，而是已拿到录取、等待签证、准备在美国工作或参加学术会议的现实选择。节目建议在未来数年的震荡期内准备替代路径，尽早评估回国、加拿大或英联邦国家等方案。

### 32:16-54:16：《地狱潜兵 2》与赛博国际主义

- 《地狱潜兵 2》由瑞典 Arrowhead 开发、Sony 发行，采用第三人称合作射击玩法。游戏初期销量和在线人数很高，但服务器准备不足、武器平衡和微交易争议，以及强制绑定 PSN 的决定，使玩家数量在几个月内大幅下降。
- 游戏的世界观借鉴《星河战队》的反讽传统：玩家以“超级地球”的士兵身份向外星种族作战，表面上是在歌颂战争，实际却保留了对军国主义宣传和权力机构的讽刺空间。新资料片把战场推进到地球，最后只剩上海、纽约等城市。
- 外星人进攻上海时，中国玩家凭借人数、游戏时间和协作能力把战线反推，随后美国、日本等国家的玩家也加入守城。玩家自发安排不同地区轮班支援上海和纽约，最终放弃纽约、全球力量汇聚上海，形成了被称为“赛博淞沪会战”的共同战斗。
- 节目认为，游戏的共同目标和相对简单的善恶框架，降低了不同国籍、种族和信仰的人建立信任的门槛。一起对抗外星人、共享语言和情绪，能让玩家直接感受到对方也是普通人，从而抵消现实宣传制造的刻板印象。
- 这场事件也暴露出开发者预设剧情与玩家真实行动之间的冲突：如果强行让上海陷落、把所有玩家赶到开发者所在的斯德哥尔摩，可能会破坏玩家共同创造出的国际主义体验。游戏公司是否愿意为玩家的意外协作改写结局，成为后续看点。

### 54:16-01:01:18：Java 三十年与 JVM 分层架构

- Java 迎来三十周年。节目承认它在工程化、学习成本和统一开发习惯方面有历史价值，但也批评 Java 表达力不足、模板代码和重复脚手架过多，很多开发者更喜欢 Ruby 等语法更简洁的语言。
- Java 真正深远的影响不只在语言，而在于“语言层-字节码-虚拟机”的分层。公开的字节码和 JVM 规范让不同团队可以实现自己的虚拟机，也让其他语言能够编译到同一种中间表示后共享运行环境。
- 这种分层把编译和执行中的复杂问题拆开，使语言前端、通用中间层和后端运行环境可以分别演进。Android 早期的虚拟机和后来的 ART，也利用了原有字节码与运行时之间的隔离来持续优化性能。
- 节目把 JVM 的思路与 LLVM、WebAssembly 联系起来：不同语言可以编译为标准中间代码，再运行在不同的 VM 或后端上。MoonBit 借助 WebAssembly 生态，也延续了这种“语言与运行环境解耦”的架构思想。

### 01:01:18-01:13:25：Java 生态、垃圾回收与 AI 争论

- JVM 的通用字节码催生了 Kotlin、Scala、Groovy、Clojure 等 JVM 语言，也让 Ruby、Python 等语言出现编译到 JVM 字节码的实现。它们可以复用 Java 生态中的大量第三方库，说明平台级抽象往往比单一语言的语法更有生命力。
- Java 的垃圾回收和内存管理是它对 C 语言指针风险的回应。节目认为 Java 语言本身未必出色，但 JVM 与字节码体系的意义非凡，足以解释它为什么在三十年后仍然拥有庞大的用户群和持续的基础设施价值。
- Java 之父 James Gosling 在纪念采访中认为，“AI”和“机器学习”这些名字过于夸张，甚至建议用“高级统计方法”替代 machine learning；他还认为绝大多数 AI 投资最终会被黑洞吞噬。
- 节目对这两个判断分别讨论：大模型确实建立在复杂统计方法上，但涌现出的不可预期能力又不能被过度贬低；至于 AI 投资，嘉宾基本同意大量资金可能无法产生与投入相称的价值。争议的关键在于如何理解“高级”统计方法，以及是否能准确描述模型能力。

### 01:13:25-01:23:37：蚂蚁开源 AI 技术版图报告

- 蚂蚁团队联合研究人员发布了一份开源 AI 技术版图报告，试图用 landscape 的形式整理快速膨胀的开源项目。项目选择、分类、类别关系和趋势判断经过了访谈、调研、数据收集与近半年的迭代。
- 报告通过 OpenRank 等指标选择了一百三十多个项目，并不仅呈现静态分类，还观察不同项目和类别在一段时间内的活跃度涨落。节目认为，这比只有框图和象限的传统技术版图更能展示生态的变化过程。
- 报告的困难来自 AI 领域变化过快：项目热度、类别边界和新工具都可能在报告完成前发生变化。一个项目是否入选也不应只看知名度或累计 Star，因为老项目可能活跃度下降，新项目则可能还没有足够历史数据。
- 维护同样是长期挑战。节目提到可以用 AI 辅助标签、分类和聚类，让版图随着新项目出现持续更新；但自动化只能降低维护成本，不能替代对类别定义和趋势结论的人工判断。

### 01:23:37-01:30:13：不能用活跃度宣布 Agent 框架退潮

- 节目建议先把 AI 技术生态分层：训练工具链、推理和服务框架等底层部分相对稳定，而 Agent 或 AI 应用开发框架以及更上层的应用仍然快速变化，评价标准尚未形成。
- 报告根据 OpenRank 观察到低代码工作流工具上升、部分框架活跃度下降，就得出 Agent 框架热潮退去、企业工作流开始主导的结论。节目认为这属于只看一个指标的“盲人摸象”，与实际开发社区的变化并不相符。
- LongChain、LongGraph 等框架确实存在学习门槛和应用成本，但并不代表整个应用开发框架方向衰落。围绕 MCP 等公共规范，新的轻量级框架正在快速出现，当前更像是进入深水区和重新洗牌，而非某条路线已经结束。
- AI 开发工具和标准协议也处于类似的混战状态，Copilot、Cursor、开源编程工具以及不同协议都可能继续变化。节目认为现在最不应做的就是过早宣布谁已经胜出或谁已经日渐式微。
- 除了衡量当前活跃度和成熟度，报告还应尝试寻找“潜力”信号。类似财务投资与风险投资的区别，现有数据适合判断已经稳定的项目，却未必能发现尚未形成规模的明日之星。

### 01:30:13-01:36:59：技术报告的正确性、传播与评价标准

- 节目建议把“有多少人关心”和“判断是否正确”作为两个不同目标。报告可以持续记录行业现象、发布有数据支持的观察，并通过拆分长文、分领域讲解和适度吸引注意力来扩大传播。
- AI 技术评测或预测专栏可以引入历史数据、模型训练和对未来项目的预测，但标题可以有一定夸张，不能建立在明显错误的事实之上。把一个尚未定型的框架领域概括成“某工具已经没戏”，既不准确，也无法真正吸引懂行的读者。
- 要判断一个 AI 应用开发框架好不好，需要结合功能、技术先进性、采用成本、维护能力、协议支持等维度。评价标准本身需要领域经验，也必须随着技术变化持续修订。
- 节目总体认可这份报告作为开端的价值，但认为它篇幅过长、内容过深，未来可以拆成多个板块和系列报告。持续收集反馈、修正分类和公开评价方法，可能比一次性给出确定排名更重要。

## 核心观点

1. 大模型竞争不只看架构是否大改。后训练、蒸馏、价格和开源许可同样可以把能力快速传递到更小、更便宜、更适合本地运行的模型。
2. 国际学术和人才流动会直接受到政策与政治情绪影响。宏观博弈最终会落到签证、科研合作、实验室运转和个人职业选择上，相关方需要尽早准备替代路径。
3. 游戏能够通过共同目标和持续协作建立跨文化的直接经验。它不一定改变现实政治，但可以让不同国家的人在共同完成任务时看见彼此作为普通人的一面。
4. 长期影响力往往来自分层和标准，而不只是表面的语言特性。Java 的 JVM、字节码和生态接口，为后来的编程语言、虚拟机和 WebAssembly 提供了可复用的架构启发。
5. 快速变化的 AI 生态不能用单一活跃度指标下定论。高质量的技术版图需要分层分类、时间序列、潜力判断、明确的评价标准和持续维护，同时诚实区分观察数据与预测观点。
