# 第153期 全球驻华办

## 内容摘要

本期从限量邀请码的 AI Agent 产品 Manus 谈起，讨论它为何在国内迅速爆红又迅速遭到质疑。节目认为，Agent 不是单独的大语言模型，而是把预编程的流程、模型推理和第三方工具编排在一起；它的效果取决于后端模型、成本、速度以及外部平台是否提供足够开放的 API。产品能否从宣传热度走向真实使用，还需要用可重复的实机体验来检验。

随后节目观察两会中 AI 话题的升温、政府网站引入 AI 数字人，以及教育体系面对 DeepSeek 时的机遇和挑战。DeepSeek 开源周发布的底层优化组件被第三方用于提升推理效率，节目认为开源的价值不在于“看起来很厉害”，而在于确实被别人采用并产生效果。围绕模型后训练、敏感议题和搜索结果，节目进一步讨论 AI 如何成为新的知识库、舆论工具和意识形态竞争场。

节目中段分享义乌之行：小商品城并不主要服务来买一两件东西的游客，而是连接全球采购、设计和生产的高效率商业网络。义乌对热点需求的响应、设计公司的产能和 AI 辅助设计让主播看到产业现场的另一种“卷”。最后讨论 Rust 进入 Linux 内核的争议，以及“换一种语言就自动更安全”的银弹神话，强调语言本身不能替代工程判断、社区协作和复杂系统治理。

## 时间线

### 00:00-23:16：Manus 爆红、宣传与 Agent 的边界

- Manus 依靠限量邀请码在技术圈迅速升温，但由于大多数人无法直接试用，热度没有像 DeepSeek、黑神话和哪吒那样形成广泛的共同体验，支持与质疑几乎同时出现。
- 节目认可它生成简历等任务的实际效果，但认为团队存在明显的过度营销，尤其是“世界上第一个真正干活的 AI”一类表述；产品尚未被中立用户充分验证时，宣传不能代替证据。
- Agent 是预先编排的程序，其中一部分任务交给大语言模型自行探索；如果编排得好，它能完成比纯模型更复杂的工作，但通常更慢、更贵，因此不能拿 Agent 直接与纯模型做不对等比较。
- 这类系统依赖高水平模型完成任务拆解和工具调度，而当前最强的模型往往成本高、响应慢；同时还依赖天气、搜索、地图、外卖等第三方 API，平台不开放就会让工作流卡住。
- 节目认为，Manus 是否成功要看它能否提高稳定性、降低成本、获得更多真实用户；听众不必为邀请码投入过多精力，等待产品开放并观察实际使用即可。

### 23:16-31:30：两会信号与 AI 进入政策视野

- 两会期间，哪吒和 DeepSeek 被各行业代表频繁提及，节目据此判断 AI 已经从民间热点上升为会影响政策和产业布局的国家议题，同时提醒也要警惕过热。
- 节目观察到春节后对台和对美关税相关的公开表述更加强硬，并把这种口径变化放在国际博弈和中美关系的新阶段中理解；具体后续仍需等待更多正式政策信号。
- 政府工作报告的 GDP、就业、通胀和赤字目标被用来观察未来几年可能增加的政策和财政动能，但主播明确把这部分作为对报告的分析，而不是已经确定的结论。
- 节目认为，AI 与两会、国家发展规划和产业转型的结合，说明社会正在进入必须认真思考“要不要用、如何用、怎样用好 AI”的阶段。

### 31:30-37:24：AI 数字人、教育与产业化

- 中国政府网推出 AI 数字人，被节目视为国家层面正式引入 AI 工作能力的信号，也会促使政府、企业和学校把 AI 使用纳入自己的工作目标。
- 节目把这一动作理解为一种可以大胆试验的“开绿灯”信号：与其等技术完全确定，不如在使用中更快区分真正的机会和无效的噱头。
- 教育部门把 DeepSeek 的成果解释为教育科研体系有效、科技发展将对人才提出新要求；节目认为这只说中了部分事实，没有充分回答教育体系如何快速、正确地改革。
- AI 对教育既是机会也是挑战，尤其当教育体系本身僵化、反应速度最慢时，学校可能不是最容易受益的行业，反而可能最容易被新技术冲击。

### 37:24-46:59：DeepSeek 开源周与真实开源价值

- DeepSeek 开源周发布了多项偏底层的算法和系统优化成果，Linux 上常用的推理部署项目 vLLM 据称利用这些成果后获得了约六七成的速度提升，显示开源组件能够直接改善行业基础设施。
- 节目区分“技术炫技”和开源价值：一个项目即使看起来很强，如果没有人采用，最多只是展示；被其他团队使用、改进并产生实际效果，才构成真正的开源影响力。
- 澎湃新闻围绕 DeepSeek 开源周采访高校教师，涉及开源大模型的含义、技术细节、行业影响、成本节约和商业持续性，说明媒体、高校和课程都被带入了这轮 AI 与开源讨论。
- 几位老师已经把大模型和开源内容加入软件工程、开源和 AI 课程，并讨论策划更系统的高校开源周；节目希望把技术热度转化为教育改革和可持续实践。

### 46:59-59:45：模型后训练、信息茧房与话语权

- 节目批评 Perplexity AI 基于 DeepSeek 做所谓“开放式”版本的做法：去掉部分敏感问题的拒答限制并加入针对性后训练，可能把模型变成带有明确议程的信息工具。
- 大模型没有传统意义上的事实概念，它是根据统计关系生成更可能出现的词语；节目因此反对用“幻觉”美化或淡化模型犯事实错误的机制，认为用户不能把模型当作事实查证工具。
- 当搜索、筛选和总结都由模型完成时，用户看到的并非未经处理的全网信息，而是经过关键词选择、内容过滤和模型价值取向加工后的结果；重复得到同一个答案也不等于答案真实。
- 节目认为，每个模型都带有训练者、数据和后训练过程中的意识形态。模型将成为一种新的知识库和舆论竞争场，社会不能再次放弃中文互联网和公共知识空间中的事实话语权。
- “机器学习”“幻觉”等术语可能让普通人误以为模型真的在学习事实、偶尔才出错；理解技术原理和检查原始证据，是避免被 AI 生成内容带偏的基本能力。

### 59:45-01:08:00：义乌的全球商业网络

- 义乌之行从全球化的餐饮生态开始：来自不同国家的采购商和商人形成稳定需求，使当地聚集了土耳其、中东、日本、欧美等多种地方风味的餐厅。
- “鸡毛换糖”被介绍为义乌商业文化的起点：早期通过鸡毛、红糖和小商品进行交换，逐渐发展为连接全球买家和卖家的商业网络。
- 小商品城拥有数量庞大的商铺，很多商家面向批发和国际采购，零售游客并不是主要客户；价格、服务和报价会根据采购规模、身份和交易意图变化。
- 义乌的标语“性价比不是用来消费的，小商品是用来赚钱的”，概括了当地商业逻辑：这里更欢迎寻找商机、进货和创造新财富的人，而不是只来走马观花的游客。

### 01:08:00-01:15:22：快速设计、AI 应用与产业现场

- 义乌正在扩建新的商品城，商铺交易和市场规模仍在增长；工业设计公司的工作效率包括一天产出数百款设计和上千个概念方案。
- 热点事件可以迅速转化为商品，通常一周内铺到全国、两周内铺到全球，说明义乌的竞争力来自需求捕捉、设计、生产和渠道之间的快速联动。
- 节目在义乌看到实时翻译、AI 辅助设计、客服和人机交互等常见应用，但认为真正有价值的 AI 可能藏在需求监测、信息筛选、辅助制造和企业管理系统里，尚未被这次旅行深入观察到。
- 低价艺术品等商品暗示着从图像生成、设计到流水线制造的连接；要理解这种能力，必须进入工厂和管理系统，而不能只看展厅里的成品。
- 义乌被形容为“全世界的驻华办”：全球商业往来带来了采购、饮食和本地化服务，也为进一步考察创新企业和 AI 生产实践留下了空间。

### 01:15:22-01:18:02：C++、Rust 与“安全银弹”

- C++ 之父回应“C++ 不安全、应全面转向其他语言”的说法，强调 C++ 社区长期积累了安全实践、补丁和标准化工作，不能把复杂语言体系简单符号化。
- 节目认为，任何编程语言都不直接等于安全；把某种语言当作解决所有安全问题的“银弹”，既可能来自政府对技术的误解，也可能来自技术圈的宗教化宣传。
- 判断语言是否适合一个系统，应该结合使用方式、团队能力、生态和具体任务，而不是只看语言名称或宣传口号。

### 01:18:02-01:29:34：Rust 进入 Linux 内核的社区争议

- Rust 被引入 Linux 内核后，C 与 Rust 两套语言需要在源代码和目标代码层面高效互操作；类型、编译过程、指针和接口约定的差异，会持续增加内核维护复杂度。
- 反对者认为，不能因为引入 Rust 就要求长期维护 C 代码的开发者同时学习另一套语言；如果社区无法明确哪种语言和接口规则优先，冲突就会扩大。
- 节目认可 Rust 在命令行工具、部分 C++ 场景和 Python 项目管理工具等方面的优势，也提到 `uv` 等 Rust 工具改善了 Python 包和项目管理体验。
- 但 Rust 仍缺少足够多的大型应用或系统级项目来证明自己能独立承载复杂生态。节目认为，与其在成熟内核中长期维持两种语言的摩擦，不如通过完整的大型项目或分支检验 Rust 的能力。
- 林纳斯把争议类比为早期 vi 与 Emacs 的偏好之争，并认为即使引入 Rust 最终失败，尝试本身也有价值；节目反对把超级内核社区当成可以随意试错的实验场，并质疑其过度集中的决策方式。

## 核心观点

1. AI 产品的宣传热度不能替代真实使用；Agent 是否有价值，要看它能否在成本、速度、模型能力和第三方工具约束下稳定完成任务。
2. 开源的核心不是发布一个看起来先进的项目，而是让其他团队能够采用、复现、改进并从中获得实际收益；底层组件的传播往往比单一产品的展示更能提升行业平均水平。
3. 大模型不是事实数据库，也不是中立的搜索入口；训练数据、后训练、检索和回答筛选都会影响用户看到的世界，原始来源和独立核查仍然不可替代。
4. 人工智能已经进入政策、教育和产业现场，但真正的挑战不是宣布“进入 AI 时代”，而是让组织改变课程、流程、评价和管理方式以适应它。
5. 编程语言没有自动带来安全，技术选择必须放回具体系统、团队协作和长期维护中评估；成熟社区引入新语言时，治理成本同样是技术问题。
