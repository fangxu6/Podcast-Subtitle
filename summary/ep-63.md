# 第 63 期 AIGC 基准测试和输入法历史

## 内容摘要

本期先从《塞尔达传说：王国之泪》谈起，回顾《时之笛》如何为三维游戏确立操作和视角的标准，以及《荒野之息》如何用地标、自由探索和自然出现的教学解决开放世界的导航问题。节目也讨论了《王国之泪》的建造系统、游戏的销量和 Switch 的硬件限制，认为真正重要的仍是玩法创新和交互设计，而不是单纯的画面规格。

随后节目分享 ChatGPT 插件的早期使用体验：插件可以根据自然语言调用外部 API、串联搜索和待办事项，也可以通过本地服务接入搜索和个人知识库。但实际开发 OpenAPI 描述文件时，调试刚刚变得可用，生成速度却慢到难以实用，说明强大的模型不一定适合每一个简单任务。围绕科大讯飞等产品的能力宣称，节目进一步讨论 AIGC 基准测试的价值：公开、分类清晰的评测能帮助社区比较模型和推动开源生态，但评测的公信力、指标设计和长期共识仍需要建立。

中段从上海高校重新开放、疫情期间形成的信息化流程，谈到 C919 试运营阶段的故障与网络传言。节目提醒听众，在舆论战和认知战更复杂的环境里，不要因为一个看似确定的结论就立即站队，应等待更多信息并听取不同意见。之后几位主播缅怀技术人陈皓（左耳朵耗子），回顾他的技术管理经历、博客分享和对年轻人的帮助，也批评通过故意激怒读者获取流量的网络表达，并提醒关注中年后的心脏健康。

最后节目回顾中文输入法的发展。拼音输入法早期受同音字影响，五笔通过字形编码提高了确定性，却把记忆编码的成本转移给使用者；智能联想和词组输入后来缩小了两者的速度差。主播还谈到中州韵等开源输入法、iPhone 早期第三方输入法，以及一位早期程序员从底层改造 Windows 输入法和搭建 BBS 的经历，感慨曾经尖端的技术最终会变成日常生活中几乎察觉不到的基础设施。

## 时间线

### 00:00-11:42：从《塞尔达》谈游戏设计的创新

- 《王国之泪》是《荒野之息》的直接续作，节目从主播刚开始游玩的体验谈到“塞尔达是天”的网络玩笑，并回顾塞尔达在任天堂作品中的地位。
- 《时之笛》面对三维场景中的人物操作、视角转换、跳跃和攻击判定，确立了双摇杆式的控制思路，后来成为许多三维游戏沿用的标准答案。
- 《荒野之息》把开放世界的两个难题同时处理得较好：用可互动的环境避免世界空洞，用出生点看到的地标和探索中自然遇到的村庄、神庙引导玩家，而不强迫玩家沿固定路线前进。
- 《王国之泪》的新系统允许玩家把材料、引擎、电池和武器等组合起来建造载具或工具；网上的夸张作品不一定代表普通玩家短时间内能复现的体验。
- 游戏发售后三天销量突破一千万。节目认为，Switch 的画面和性能并不突出，但创意、系统设计和交互仍然能让作品成为现象级产品。

### 11:42-27:42：ChatGPT 插件与个人知识库实践

- ChatGPT 插件当时仍处于分批开放状态，使用者可能需要付费、等待资格；插件目录从最初的十几个逐渐扩展到百余个，但质量和实用性差异很大。
- 插件的基本模式是让模型根据用户意图调用外部 API，并展示插件、输入参数、输出结果和执行结果；例如先查找餐厅，再把排名第一的结果写入待办事项。
- 官方浏览器功能与插件不能同时使用，WebPilot 因而被当作浏览器搜索的替代方案，使用户可以在搜索的同时混用其他插件；本地搜索插件则通过 localhost、跨域配置和搜索 API 接入模型。
- 主播原本想把多个开源项目表做成知识库，只先实现一个项目表的 CRUD 服务，过程中经历了 Python ORM 读取字段异常、Ruby/Sinatra 的跨域配置和 OpenAPI YAML 调试等问题。
- 即使最终把调用链调通，模型逐字生成配置和调用代码仍然需要几分钟甚至更久。节目认为，用远超任务所需复杂度的模型去完成简单工作，会让结果失去实际价值。

### 27:42-40:51：AIGC 基准测试的价值与边界

- 节目讨论科大讯飞关于国内大模型能力接近 ChatGPT、并尝试把语言模型与认知模型结合的说法；主播认可其中文分词和自然语言处理积累，但对过于乐观的时间表保持怀疑。
- 大模型基准测试沿用了计算机性能评测的思路，用跨学科的标准题目比较模型能力；通用测试之外，还可以针对数学推理、教育等具体领域建立专项评测。
- 节目介绍了 Papers with Code 上的 MMLU 排名，当时列出的 GPT-4 得分为 86.4，PaLM 相关版本为 81.2。主播认为，公开榜单让普通开发者也能比较开源模型，并推动模型和评测一起迭代。
- 基准测试不能自动获得权威性：题目、答案、领域分布和评分方法都可能偏向某类模型。更可行的做法是公开规则、拆分能力维度，并让研究者和社区在持续比较中形成共识。
- 自然语言理解开始尝试用接近人类理解力的标准评估，但如何把“理解”定义为可量化、可复现的指标，仍是早期且需要长期研究的问题。

### 40:51-43:43：校园重开与疫情后的信息化

- 上海高校在经历约三年的疫情管控后重新开放，校外人员可以凭身份证进入，原先的审批和校友卡限制明显减少。
- 疫情期间，学校把健康申报、人员进出审批等原本依赖纸张的流程做成校园系统，后来又推进到微信端，客观上提升了学校的信息化程度。
- 为了避免人员堵在门口，不同部门之间需要共享信息、处理异常情况；持续解决这些实际问题，也推动了流程和部门协作的改善。

### 43:43-48:31：C919 传言与复杂的舆论环境

- C919 取得适航证后，首架交给东航进行最后阶段的飞行测试，起飞后不久出现异常并未直接等同于项目失败，但网上很快出现交付延期、订单无法兑现等夸张传言。
- 主播结合对相关工作人员的了解和对中国工程能力的判断，认为测试阶段出现故障并不罕见，具体问题仍应等待后续交付和运营信息验证；节目也提到国产核心部件替代方案正在进行试飞测试。
- 随着飞机继续交付并接近正式商业运营，节目把这个案例延伸到信息判断：不能把网上看起来很完整的说法当成事实，也不能只依据单一来源下结论。
- 主播认为，网络舆论战和认知战的烈度正在上升。面对突然出现的争议和耸动结论，应多等一等、交流不同意见，再决定是否相信或转发。

### 48:31-01:00:23：缅怀陈皓与技术人的成长

- 陈皓（左耳朵耗子）曾在 Amazon 北京研发团队担任技术经理，经历了国内软件企业从作坊式开发逐渐引入工程流程、标准化和敏捷实践的阶段。
- 他长期留在技术一线，后来创业做技术产品；虽然几位主播不一定认同他的全部架构和管理观点，但都认为他热心、愿意认真帮助刚入行和刚开始带团队的年轻人。
- 陈皓经常在博客中分享技术经验，也曾与开源、技术管理和企业文化相关的社区保持联系。节目回忆他早年很少愿意出书，认为自己还没有达到可以系统写书的程度，后来才开始制作课程和内容。
- 他在阿里的经历与个人偏好并不完全匹配，节目借此说明，技术能力强、技术判断独立的人不一定适合所有组织环境；职业选择还要看工作方式和组织文化是否相容。
- 主播对他的突然离世感到惋惜，并提醒听众不要把技术人的长期工作、分享和帮助视为理所当然。

### 01:00:23-01:05:53：网络愤怒、流量与表达责任

- 节目回应一篇贬低陈皓、指责他把时间花在社交媒体和新技术上的文章。主播认为，业余学习、刷题、做开源项目或帮助年轻人，并不等于把人带上“邪路”。
- 几位主播判断，文章中的极端说法更像是故意制造争议和人设：赞同者往往只留下简短支持，愤怒者却更愿意长篇反驳，因此骂人可以带来更高的互动和传播。
- 这种表达方式的欺骗性在于，读者若不了解相关领域，可能会把自信和强烈措辞误认为专业判断；评价观点仍需要检查事实、论证和作者是否真正理解对象。
- 节目也反思了转发争议文章会帮助其获得传播，提醒听众在愤怒时先判断自己是否正在替对方完成流量目标。

### 01:05:53-01:07:54：健康提醒与告别

- 陈皓在睡眠中因心肌梗塞去世，节目提到这类突发问题的救治窗口可能很短，因此不应忽视身体发出的异常信号。
- 主播建议成年人至少每年体检一次，心脏和血管相关问题要及时检查和治疗；已经很疲劳时临睡前进行剧烈运动，也可能增加风险。
- 新冠感染后出现心慌、心律不齐等情况的原因需要具体判断，节目没有把它当作确定病因，但提醒听众对持续或明显症状保持警惕。

### 01:07:54-01:14:43：拼音、五笔与输入法的速度

- 三位主播分享了电脑和手机上的拼音、九键、语音输入以及搜狗、讯飞等输入法，也回忆学生时代学习五笔和用打字软件练习输入的经历。
- 早期拼音输入法会产生大量同音字候选，在机器性能和字库都有限的年代，用户需要从屏幕列表中寻找目标字，输入速度因此受到限制。
- 五笔根据汉字字形拆分编码，通常最多四个键就能定位一个字，减少同音字选择；它的代价是用户必须记住复杂的字根和拆字规则，学习门槛较高。
- 拼音输入法加入词组联想、按词频推荐和简拼后，输入单位从单字变成词，候选数量显著减少，熟练五笔与智能拼音之间的速度差也缩小了。

### 01:14:43-01:23:03：开源输入法与早期系统实践

- 主播曾因搜狗不开源、具有商业化和广告背景，并且需要较高权限而担心键盘输入隐私；后来因为移动端滑动移动光标等便利功能，最终接受了它，也认为系统自带输入法已经足够实用。
- 中州韵（Rime）支持多种操作系统，但长期缺少面向普通用户的图形配置界面，需要手写类似 YAML 的配置文件。主播曾为 Mac 版本编写配置工具并开源，项目一度获得六百多个 star。
- 在 iPhone 尚未开放第三方输入法、甚至没有正式 SDK 的时期，开发者通过越狱社区编译并安装中文输入法，说明输入法曾是需要深入系统底层才能完成的复杂软件。
- 早期中文输入法经历了“万码奔腾”：仓颉、五笔和各种字形编码方案不断出现，用户会把尝试新编码当作一种技术兴趣；如今系统输入法已成为日常中几乎不可见的基础设施。

### 01:23:03-01:27:16：早期黑客与技术进步

- 主播回忆 1997 年遇到的一位中科大少年班博士：他在 Windows 95 中发现没有自己习惯的五笔编码后，当场研究字库并把编码库转换成系统能够使用的格式，一个下午就完成了改造。
- 这位程序员后来边学习图形界面技术，边利用数据库内置的 PL/SQL 做出公司第一个可以通过浏览器访问的 BBS，系统长期运行且几乎没有 bug。
- 节目认为，早期黑客常常直接面对操作系统和底层接口；今天的顶尖技术人员则可能把精力投入大模型等新的基础设施。技术进步会把曾经尖端的工具变成普通人习以为常的能力，然后把注意力推向下一个边界。

## 核心观点

1. 真正的游戏创新通常来自重新定义操作、导航和交互，而不是单纯提高画面规格；成熟的系统设计会让复杂机制变成玩家自然理解的体验。
2. 基准测试的价值在于提供公开、可比较、可持续迭代的竞技场，但一个分数不能代表模型的全部能力，评测规则和指标本身也需要接受检验。
3. AI 工具能调用更多外部能力，并不代表它适合所有任务。任务越简单，越需要匹配合适的工具、控制调用成本，并由人判断结果是否值得采用。
4. 面对网络上的确定性结论和强烈情绪，应区分事实、推测与表达策略；等待信息、核对来源和听取不同意见，是降低误判和被操纵风险的基本方法。
5. 输入法和早期系统工具的历史说明，很多技术会从少数人的底层创造变成日常中不可见的基础设施；技术的成熟不是消失，而是被稳定地融入生活。
