# 第 78 期 华为的“偷袭”

- 来源：`transcript-site/episodes/ep-78.html`
- 时长：01:34:45
- SRT 条目：531
- 阅读段落：124

## 内容摘要

本期先补充上期的福岛核处理水排海话题，讨论东京电力公司的责任、事故应急中的一系列失误，以及日本政府和东电需要回答的三个核心问题：排放水的完整成分、海洋和生态影响的科学证明、以及污染水和反应堆后续处理的明确计划。节目认为，争议的关键不只是某一项指标是否低于标准，还在于数据是否由独立第三方采集、方案是否经过充分验证，以及日本是否真正承担了跨国风险的说明责任。

随后节目介绍国产编程语言 MoonBit（月兔）。它以函数式编程为基础，面向 WebAssembly 和云端开发，强调快速编译、自动内存管理、在线试用和未来的云原生开发体验。节目将其与迟迟没有公开的其他国产语言对比，认为真正值得关注的国产软件应从明确的科学和工程问题出发，尽早进入社区交流，而不是把“国产”停留在宣传口号上。

节目主体讨论华为突然发布 Mate 60 Pro。围绕麒麟 9000S、5G 连接、先进制程、EDA 软件、多次曝光和芯片代工等问题，主持人区分了测速和拆机可以确认的部分、芯片来源和工艺的推测，以及尚未公开的事实；卫星通信则被认为比芯片本身更快具有普通用户可感知的价值，也可能成为下一代移动通信的重要入口。节目同时提醒，Mate 60 Pro 的历史意义和日常实用性并不相同。

最后讨论 IDE 的演进。Visual Studio for Mac 停止支持的新闻被认为带有标题党色彩，但它引出 IDE 从字符界面、图形界面、插件化到联网、云端和 AI 协作的发展过程。节目认为，未来开发环境会降低本地配置门槛，把代码、部署、协作、审查和智能工具连接起来；VS Code 的开放生态、语言服务协议和微软长期积累，使其在这场变化中仍占据明显优势。

## 时间线

### 00:00-12:46：东电责任与福岛排海的三个问题

- 节目补充东京电力公司的背景：福岛事故后电站无法正常运营，还要承担赔偿和重建成本，日本政府通过专门机构注资，东电因此实际上与日本政府利益深度绑定。
- 主持人回顾事故初期的应急失误，包括没有及时停堆、备用发电机设置在容易被海啸淹没的位置、移动电源接口不匹配，以及缺少向堆芯注入海水的设备；节目还指责东电曾隐瞒堆芯熔毁和污染水泄漏风险。
- 面对日本方面以“科学”和单项指标回应质疑，节目提出三个应被白纸黑字回答的问题：排放水到底包含哪些成分，是否有独立第三方采样检测；海洋、大气和生态影响是否有长期实验和同行评议；排放三十年的计划如何保证反应堆被处理、污染水不再持续产生。
- 节目认为，只公布氚含量、把其他核素排除在叙述之外，不能替代完整的成分说明和长期影响证明；“低于安全线”也不能自动推出对海洋生态长期无害。

### 12:46-24:29：MoonBit 与国产编程语言的路径

- 节目介绍 MoonBit（月兔）的初步体验：语法相对干净，编译速度快，提供在线运行示例，并以函数式编程和 WebAssembly 为主要目标，适合云计算环境。
- MoonBit 的主创张洪波此前参与 OCaml、ReScript 等语言和工具，项目希望把函数式语言编译到 WebAssembly，使程序可以在浏览器和云端环境运行；其背后机构还在研究云环境下的一体化开发系统。
- 节目将 MoonBit 的公开交流方式与华为内部长期打磨、但没有明确公开时间表的语言作对比，认为开源项目应尽早接触潜在用户和社区，在真实反馈中迭代，不必等到“完美”才出现。
- 主持人认为，国产编程语言不必刻意追求中文关键字或表面上的中国特色，更重要的是找到尚未被很好解决的科学和工程问题，做出可靠、有独特价值的产品。
- 对计算机教育而言，云端、零配置、可直接运行的环境便于分享、二次创新和教学；未来还可能围绕可复制的应用模板，进一步连接 AI 编程能力。

### 24:29-27:56：云端 IDE 与下一代编程体验

- 节目设想的云端开发环境应覆盖设计、编程、测试、部署和调试，用户只需通过浏览器连接服务，不必在本地反复配置环境。
- 应用模板可以像容器一样被复制、修改和即时运行，满意后再一键发布到生态环境；这种完整链路也更适合接入 AI，而不只是让 AI 补全一个函数。
- 云端环境能把不同账号、依赖和部署环节统一起来，使 AI 更容易参与完整工作流，也能降低教学和团队协作的门槛。
- 节目认为，MoonBit 在线 IDE 的响应速度和使用体验已经显示出一定信心，但项目仍处于早期阶段，后续能否形成公开生态还需要观察。

### 27:56-39:15：生成式 AI 的首批应用与安全边界

- 生成式人工智能管理办法要求相关模型和服务备案，首批十几个国内大模型完成备案后，多个面向公众的 App 陆续上线，普通用户可以直接试用。
- 主持人测试文心一言的图片理解和网络梗图，发现它会把白天照片说成夜景，也会对涉及企业负面信息的问题设置明显防护；但网上流传的截图可能是旧版本、特殊提示词或造假，不能只凭图片下结论。
- 各家模型都需要安全边界，以限制不可预测的主观评价、政治和风险内容；不同公司在防护强度和表达方式上有差异，但防护并不能阻止所有外部舆论继续传播未经核实的说法。
- 目前国内大模型在编程方面仍被认为较弱，但格式化文本、课程大纲优化、垃圾邮件分类、数据格式转换和一些小型自动化任务已经有实用价值。
- 节目认为，模型现阶段更需要高质量、聚焦的真实使用场景，而不是急于通过办公助手等产品收费；持续使用和反馈才能推动模型迭代。

### 39:15-47:23：Mate 60 Pro 发布与 5G 连接

- 华为突然发布 Mate 60 Pro，发布时间早于原本预期的发布会，迅速引发开箱、拆机、测速以及供应链和技术封锁方面的讨论。
- 多组测试显示，手机移动网络下载速度达到五百兆甚至更高；结合关闭运营商 5G 通道后速度下降、重新打开后恢复，以及拆机发现海思麒麟芯片等信息，节目判断它具备 5G 通信能力。
- 华为过去受限于无法获得先进制程，难以把体积更大的 5G 基带与 CPU、GPU 集成在同一 SoC 中；这次重新出现集成 5G 的芯片，说明相关研发和制造链条可能持续存在。
- 节目提醒，华为没有公开芯片工艺和来源，早期硬件识别工具把它显示为五纳米，可能只是误认成旧款麒麟芯片，不能据此确认麒麟 9000S 的真实制程。

### 47:23-56:31：麒麟 9000S、制程与 EDA

- 主持人认为，麒麟 9000S 不太可能只是制裁前囤积的旧芯片，因为囤货无法支撑长期供应；但芯片究竟在哪里生产、使用了何种工艺，仍是华为刻意保留的悬念。
- 节目解释“几纳米”在先进制程中更多是代表单位面积内晶体管密度和工艺代际，不应简单理解为芯片上真的刻出了相同宽度的元件；所谓接近七纳米的效果，可能通过多次曝光等方法实现。
- 芯片产业的突破不只依赖光刻机，还涉及 EDA 软件、设计流程、模拟测试、制造工厂和良品率。节目推测，华为可能已经建立了从自有 EDA 到芯片设计、再到多次曝光制造的完整流程。
- 节目提到国内仍可获得部分 28 纳米 DUV 设备，华为和相关企业可能利用多次曝光做出接近过去旗舰芯片密度的产品；关于具体代工厂和参与公司，主持人明确表示目前只能推测。
- EDA 的难点不仅是写出软件，还要让芯片工厂愿意使用、能把设计数据准确交给生产设备。制裁反而迫使华为投入到过去依赖外部供应商的工具链和工艺协同中。

### 56:31-01:00:55：卫星通信的实际价值

- Mate 60 Pro 支持中国电信运营的天通卫星通信。过去这类能力主要依赖带有长天线的专用设备，如今被放进普通智能手机，使用门槛明显下降。
- 节目介绍的新套餐月租约十元，通信时按分钟收费，更像平时不使用、关键时刻用于求救或应急联络的低价保险；这与专业卫星电话的高月租和高单价形成对比。
- 主持人认为，芯片工艺突破的历史意义很大，但普通用户未必能直接感受到；卫星通信则可能在没有地面网络的场景中立即提供价值，也会促使运营商继续投入。
- 地面网络与卫星网络融合被视为下一代移动通信的重要方向，Mate 60 Pro 的卫星功能因此被节目看作提前发出的信号，而不只是一次旗舰手机的附加功能。

### 01:00:55-01:10:12：发布时机、供应链与开放生态

- 节目讨论华为突然发布的几种可能原因，包括在美国商务部门相关人员访华期间展示技术突破、配合半年报，以及抢先占据苹果和其他厂商发布会的注意力；这些都被明确视为推测，不能当成确定动机。
- 华为敢于先卖出数百万台手机，意味着它需要有足够的芯片生产和代工能力；后续能否扩大到数千万台，将成为判断供应链是否真正打通的重要观察点。
- 芯片被制裁后，海思团队并没有像外界传言那样消失，可能从单纯做芯片设计扩展到工厂协作、生产磨合和全流程建设；另一部分公司则可能因管理层立场和美国监管压力放弃相关业务。
- 节目还提到，有企业希望围绕新的国产操作系统做开源生态。卫星通信设备若采用开放系统，可能帮助形成底层通信规范和应用生态，但具体技术方向仍属于主持人的推测。

### 01:10:12-01:16:21：国产替代与购买建议

- 节目以国内 GPU、Julia 等相关项目为例，认为不同领域正在形成相互连接的国产软件和硬件研发网络；据节目提到的报道，三十五项“卡脖子”课题中已有二十多项取得基本突破，但这类数字仍应结合具体项目理解。
- 主持人判断，足够大的市场和研发能力使长期封锁很难永久阻断产业发展，但第一代国产替代产品通常会在能耗、软件兼容和使用体验上存在代价，需要继续迭代。
- 对普通消费者，Mate 60 Pro 的历史意义和实用价值应分开看：它的性能可能比同期高通旗舰落后一到两年，部分游戏和软件兼容性也需要通过更新改善。
- 如果重视卫星通信、愿意为历史节点和新功能付费，可以考虑购买；如果只是需要日常好用的手机、预算有限或不急于体验新功能，节目建议等待后续产品和运营商服务普及。

### 01:16:21-01:26:42：IDE 的历史与标题党

- “宇宙第一 IDE 放弃 Mac”实际指 Visual Studio for Mac 将于 2024 年 8 月 31 日停止支持。节目认为，这种标题利用大标题、小标题和配图制造震惊感，却没有说明该产品在 Mac 开发者中的真实使用范围。
- 主持人回顾从 Turbo Pascal、Delphi、Visual Basic、Visual C++、Visual Studio，到 Java IDE 和 Mac 上 TextMate 的经历，说明 IDE 从编辑、运行、调试一体化环境逐步发展而来。
- 过去区分 IDE 和普通编辑器的标志之一是断点、单步调试等能力；随着 VS Code、Emacs、Vim 和 JetBrains 工具扩展功能，纯编辑器和 IDE 的边界已经越来越模糊。
- IDE 的发展还经历了插件化、联网升级和云端服务阶段；Copilot 进一步把远端 AI 知识库接入开发环境，使 IDE 从本地工具变成连接外部能力的平台。

### 01:26:42-01:34:45：VS Code、云 IDE 与协同编程

- 节目认为，VS Code 的成功不只是界面或免费策略，还建立在语言服务器协议、IntelliSense、插件生态、GitHub 和微软长期投入的基础上；社区版 Visual Studio 也让很多开发者无需付费即可获得完整能力。
- IDE 连接云端后，开发者可以共享代码、进行实时或异步代码审查，并让其他人或 AI 在开发过程中参与修改和讨论；桌面 IDE 与 Web IDE 的界限会因此逐渐消失。
- 下一代开发环境应降低本地部署门槛，把代码库、远端服务、协作、部署和 AI 工具放在同一条链路中；云端环境的开箱即用和社会化协作可能成为重要方向。
- 节目判断，VS Code 已通过插件和开放生态连接了几乎所有技术领域，其他工具很难在短期内撼动它；但 Web IDE 体验持续改善后，未来仍可能出现新的竞争空间。

## 核心观点

1. 国产软件的价值不在于名称和口号，而在于是否针对真实的科学或工程问题建立了可维护、可交流、可持续演进的能力。
2. 技术突破应区分已验证的测试结果、基于产业链的合理推测和尚未公开的事实；只有把软件工具、制造流程和供应链一起打通，单点成果才可能规模化。
3. 复杂公共风险不能靠单项指标和权威口号消除疑虑，完整成分、独立采样、长期实验和明确的后续计划才是建立信任的基础。
4. 大模型的价值要通过真实、聚焦、可反馈的使用场景检验。模型备案和安全边界是基础，领域数据、用户反馈和持续迭代同样重要。
5. 编程工具正在从本地 IDE 走向云端、开放生态和 AI 协作；未来的竞争不只在编辑器功能，也在于谁能提供完整、低门槛、可连接的开发链路。
