## 内容摘要

本期节目从朱雀三号可回收火箭的成功回收，谈到中国商业航天距离真正实现重复使用和工业化还有哪些环节；随后讨论《黑神话：钟馗》的实机预告、国产 3A 游戏的技术积累、战斗交互和宣发方式，并以《影之刃零》作对比。

节目中段转向知识传播和文化评论，讨论“种树”相关争议、表达能力与知识积累的关系，以及诺兰电影和《奥德赛》的话题。之后讨论下一代 Agent 的方向，重点是企业级 Agent、知识沉淀、权限和工作流，以及 Agent 架构中执行循环、上下文管理、工具调用和模型适配四个核心模块。

最后是读书环节，推荐科幻小说《我们生活在南京》和《挽救计划》，以及介绍规范驱动开发（SDD）的《规范驱动的开发之道》，强调在 AI 编程中先明确需求、设计和任务，再让 AI 执行并由人负责审核和验收。

## 时间线

### 00:00-13:03：朱雀三号与可回收火箭

- 朱雀三号第二次尝试完成了一级火箭回收。上一次发射的前段过程已经接近成功，但最后点火阶段出现问题；这次完成了姿态调整并准确落地。
- 火箭采用液氧甲烷燃料和不锈钢箭体。甲烷充分燃烧后主要生成气体和水，箭体相对干净，也更适合后续清洗和复用。
- 一次成功回收不等于已经实现重复使用。后续还要处理回收后的箭体、重新加注燃料并再次发射，先跑通“回收-复飞”的闭环，再提高同一箭体的年发射次数。
- 中国与 SpaceX 的差距需要分开看：近地轨道通信卫星这类高频发射场景正在接近，但星舰代表的超重型火箭仍涉及应用场景、成本和回收性价比等问题。
- 讨论认为，比较合理的判断是用两三年逐步完成复用闭环并开始上量，而不是用“大跃进”式的时间表判断技术进展。真正进入工业化，还要靠稳定的发射频率和规模验证。

### 13:03-55:28：国产 3A 游戏与《黑神话：钟馗》

- 国产 3A 游戏正在出现一轮集中爆发，《黑神话：悟空》的成功提高了行业和玩家对后续作品的期待，也给其他开发团队带来了很大的压力。
- 《黑神话：钟馗》的 15 分钟实机预告展示了群战、中型 Boss、格挡、闪避、处决动作、场景光影、水体效果和大量动作派生。节目认为它既是在展示技术，也是在展示游戏真正可玩的部分。
- 游戏不应只追求电影式画面。优秀的游戏应该把玩家操控、预先设计的脚本和过场演出自然地衔接起来，让交互成为核心，而不是用特效和剪辑掩盖交互不足。
- 《黑神话：钟馗》的预告片中有大量细节和幽默感，主角身份、人物关系以及世界观仍保留悬念。节目还讨论了其中可能对《血源诅咒》等作品的致敬。
- “走投无路加大密度”可以概括一种制作策略：当暂时不知道如何继续突破时，把已经验证有效的内容做得更多、更丰富、更扎实，例如增加动作派生和 Boss 攻击模组。

### 36:27-55:28：对《影之刃零》的期待与担忧

- 节目认可《影之刃零》的武侠动作方向，但认为官方预告片没有充分展示核心卖点。相比之下，IGN 中国的试玩视频因为完整呈现潜行、跳跃攻击、武器组合和 Boss 战，更能让观众理解游戏的玩法。
- 动作游戏的战斗场景应尽量清楚，玩家要看见敌我动作和交互结果。过多的光污染、粒子效果和电影化镜头会削弱玩家对战斗的判断。
- 游戏的配乐和宣发同样重要。节目认为《黑神话：钟馗》的配乐和预告片节奏很有记忆点，而《影之刃零》在这些方面仍有改进空间。
- 开发商可以与平台方合作，但宣发的核心判断不能完全交给平台。面向中国市场的作品也应准备充分的中文宣传内容。
- 《黑神话：悟空》的成功不应导致所有团队都拥挤到同一种 ARPG 模式中。国产单机游戏仍有从小成本、小众作品到大型商业作品之间的广阔空间。

### 55:28-01:20:07：知识表达、争议与诺兰电影

- 节目讨论一位因采访诺兰而受到关注的内容创作者，并以其政治学节目中的相关言论为例，讨论表达能力、知识基础、事实核查和长期积累之间的区别。
- 节目认为，表达自信、能够快速提出观点，并不等于观点可靠。跨学科阅读如果缺少持续沉淀，容易变成只会抓取概念、缺乏基本常识和论证的“知识表演”。
- 对观点的批评本身没有问题，但应建立在对被批评对象的基本理解和事实依据之上，而不是用强烈措辞替代论证。
- 诺兰的《奥德赛》引发了关于古希腊神话、文明兴衰和电影视角的讨论。节目也回顾了诺兰从《追随》《记忆碎片》《蝙蝠侠》到《盗梦空间》《星际穿越》《奥本海默》的创作变化。
- 节目强调，不喜欢或看不懂一部作品是正常的；不能因为自己理解了，就把理解作品变成对观众的优越感，也不能把看不懂简单归咎于观众。

### 01:20:07-01:45:44：下一代 Agent 与企业级应用

- 第一轮 Agent 热潮已经形成较稳定的产品格局。下一代 Agent 如果只是重复现有产品的能力，很难形成真正的差异。
- 目前流行的多数 Agent 面向个人用户，未来更值得关注的方向是企业级 Agent，尤其是企业知识沉淀、工作流程、组织权限和协作方式的整合。
- 企业级应用的难点不只是技术。很多企业没有清晰的组织架构、岗位职责和流程；企业对 IT 投入谨慎；真正适合作为试点的优质客户也很难找到。AI 变化过快，也会让企业担心今天的投入很快过时。
- 企业 Agent 不应只是个人桌面上的工作台和插件集合，而应有统一的控制面，关联员工账号、部门、项目组、知识库、权限和不同层级的记忆。
- 节目认为，一个 Agent 的核心架构可以抽象为四部分：
  1. 执行循环：任务如何进入循环、执行和结束。
  2. 上下文管理：如何插入、筛选、压缩和淘汰上下文。
  3. 工具调用：如何选择工具、处理输入输出并控制调用成本。
  4. 模型适配：针对不同模型的行为差异调整消息组织和调用方式。
- 可观测性、插件热加载、开放标准支持等能力应尽可能放在底层架构中。记忆、多 Agent 协作等功能更适合作为扩展层，不必强行纳入所有 Agent 的核心标准。
- 下一步最值得突破的部分可能是智能化的上下文管理：在上下文不断增长时，准确保留重要信息并淘汰过期内容。

### 01:45:44-02:00:01：《我们生活在南京》

- 这是一本从起点连载开始的国产科幻小说，设定是业余无线电爱好者与二十多年后的未来女孩取得联系。
- 未来世界已经毁灭，只剩下生活在南京的女孩。故事围绕两个时代之间如何确认身份、传递信息、埋藏和取得物品，以及如何调查末世原因展开。
- 小说中关于“时光慢递”的设计很有吸引力：信息和物品既要能够在二十多年后被目标人物找到，又要防止被第三方提前获取或篡改。
- 节目喜欢其中基于无线电、物理和工程细节展开推理的部分，也认可女主角在困境中的行动和坚持。
- 节目不太喜欢小说最后偏宿命论的结局，认为如果所有努力都只是历史已经决定的结果，会削弱行动和选择的意义；但整体仍认为这是一部值得阅读的科幻作品。

### 02:00:01-02:07:43：《挽救计划》

- 《挽救计划》（Project Hail Mary）是安迪·威尔的作品，作者还写过《火星救援》。节目介绍了作者从程序员和个人网站连载起步，后来通过 Kindle 出版并获得关注的经历。
- 故事从一名在太空船中醒来、失去记忆的主人公开始。他通过身边的证据、观察、实验和推理，逐步弄清自己是谁、为什么在那里，以及地球面临什么问题。
- 作品的魅力在于把硬科幻设定、解谜过程、人物关系和情感叙事结合起来。电影改编对原著中的复杂科学细节有所取舍，但保留了悬念、温暖和合作主题。
- 节目建议：如果不熟悉故事，可以先看电影建立整体印象，再阅读小说补充科学设定；喜欢硬科幻和详细技术推演的读者也可以直接从小说开始。

### 02:07:43-02:18:55：规范驱动开发（SDD）

- 最后推荐的《规范驱动的开发之道》讨论如何把 AI 编程从快速试验推进到更可靠的工程实践。
- SDD 的基本流程可以拆成三个 Markdown 文档：
  1. 需求文档（proposal）：要解决什么问题、用户是谁、核心功能是什么。
  2. 设计文档（design）：产品如何工作，包含架构、数据和技术方案。
  3. 任务清单（tasks）：把大目标拆成可以按顺序执行和验收的小任务。
- 在这种模式中，AI 更像执行者，人仍然是产品经理、设计审核者和质量负责人。人需要检查需求是否准确、设计是否合理、实现是否符合预期。
- 规范驱动开发适合复杂、需要长期维护、工程质量要求较高的项目；简单的实验和一次性页面仍可以使用更轻量的 Web Coding。
- AI 编程时代的工程素养重点会逐步扩展到需求分析、规范表达、架构设计、技术决策、结果验证和质量控制。编码实现仍然重要，但不再是唯一的核心能力。

## 核心观点

1. 技术演示只是起点。火箭需要从成功回收走向反复复用，游戏需要从技术展示走向稳定交互，Agent 需要从个人工具走向可落地的企业协作。
2. 规模化依赖闭环和验证。一次成功、一个精彩预告片或一个插件生态，都不能直接等同于成熟的工业化产品。
3. 内容表达需要知识积累和事实核查。表达有感染力可以帮助传播，但不能替代论证、常识和长期沉淀。
4. AI 越强，前置的需求和设计越重要。让 AI 直接生成代码可以提高速度，但清晰的规范、可执行的任务和明确的验收标准，才决定最终结果是否可靠。
