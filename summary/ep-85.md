# 第85期 更多选择更多快乐

## 内容摘要

节目从加沙医院遭袭后的舆论变化谈起，先区分医院伤亡、责任归属和媒体叙事，再讨论美国公众对单方面支持以色列的态度变化。话题随后转向一带一路十周年，主持人把它与开源的发展过程类比，认为长期做事、形成真实能力和持续提供选择，比单纯模仿或争夺舆论更重要。

接着节目分析美国新一轮高端算力出口限制：规则改用 FLOPS 衡量算力、扩大限制范围并加入新的中国 GPU 企业。讨论认为，限制会立刻影响显卡获取，但不可能让中国 AI 停止；真正的挑战是用几年时间补齐 GPU、软件工具链和产业协作，不能把华为的突破理解成“躺赢”。

节目中段集中讨论开源社区和代码托管平台，包括开源开发者传承、开源教育、GitHub 的替代者以及“群智开发模式”。最后用较长篇幅解释 Android、AOSP、GMS、Linux 内核、虚拟机和应用分发之间的关系，认为鸿蒙和小米 HyperOS 可以被看作 Android 同源而逐渐分化的子生态，不能用“是不是套壳”这一句口号替代技术分析。

## 时间线

### 00:00-17:32：加沙医院事件、舆论转向与一带一路

- 节目从加沙一所医院遭袭、造成数百人死亡的事件开始，指出以色列方面承认伤亡事实但否认由己方攻击，责任归属因此成为舆论争论的中心。节目强调，即使医院内可能有武装人员，也不能因此忽略病人、医生和其他平民的伤亡。
- 讨论观察到，BBC、纽约时报等西方主流媒体的相关报道受到原有受众反向质疑。节目把传统媒体和 Twitter、TikTok 等新媒体的资本与传播结构差异作为一种解释，但也承认其中不少属于推测。
- 节目进一步讨论美国“边疆精神”及其与西部拓展、殖民和征服叙事的关系，并提到美国和欧洲部分公众、大学生及高中生开始更坚定地支持巴勒斯坦；美国国务院一名资深官员的辞职被拿来与麦卡锡主义时期的舆论转向作比较。
- 节目以北京举行的一带一路十周年活动为对照，提到约 150 个国家参加，并引用复旦大学教授黄仁伟的观点：过去十年的建设可能减轻了全球市场衰退、疫情经济后果和中国企业出海受到的冲击。
- 主持人认为，一带一路经历了基础设施、标准化、营商关系和海外经营方面的长期试错，已经不再是很容易被外部力量掐断的项目。应对舆论优势也不必复制对方的媒体形式，更重要的是持续做出正确且可验证的事情。

### 17:32-31:21：高端算力限制与算力自主

- 美国对高端算力的规则更新，修改了原来主要参考 GPU 与内存带宽的衡量方法，改用 FLOPS，并明显降低门槛，消费级 RTX 4090 也被纳入讨论范围；同时对受限人员和新增实体名单作了更清晰的界定。
- 节目判断，这些政策会直接减少中国可以买到的高端 GPU，但战略目标更可能是拖慢 AI 和自主 GPU 的发展，而非永久阻断。华为从芯片受限到拿出替代方案的经历，被用来说明四五年时间既可能造成明显压力，也可能反过来促成产业突破。
- 受访者认为，受限制的 GPU 企业需要有类似华为的研发、市场和生态投入能力，不能只等待政策变化带来机会；短期会有显卡和计算资源的困难，长期则要补齐芯片制造、软件和应用侧的缺口，AI 企业也要参与把依赖 CUDA 的软件迁移到可控的国内软件层。
- 主持人反对“华为躺赢”的爽文式叙述，强调鸿蒙、5G 芯片等成果背后有长期研发和高强度工作。禁令可能迫使原本能够直接购买和借鉴的技术全部重新实现，短期反而会更痛苦。
- 节目认为，禁令升级也可能让行业更容易形成共识：要么继续获得外部算力，要么联合起来完成替代方案；华为先取得突破的象征意义，会降低后来者投入的心理门槛。科技代际变化的具体时间、地点和完成者无法准确预测，但外部限制至少会迫使产业发展自己的解决方案。

### 31:21-44:15：开源大会、开源教育与数字素养

- 节目介绍 CCF 开源大会、天宫开源相关活动和即将举行的中国开源大会。CCF 开源发展委员会成立三年后首次线下开会，现场约有千人，说明疫情后开源社区正在重新建立面对面的交流网络。
- 大会讨论了算力网、OpenHarmony 和高性能计算，也让主持人看到不少开源项目已经在高校制度中落地。武汉大学、华中科技大学和浙江大学等学校开始尝试把学生的开源贡献与保研、奖学金或成长评价联系起来。
- 节目认为，开源仍是一个小众实践，但它包含社会共同创作、分享以及公益与商业并存的普世方法。未来需要把这些方法提炼成更通用的数字素养和协作教育，而不只是反复使用“开源”这个标签。
- 讨论提出，计算机教育面对一个矛盾：有些人十几岁靠自学就能做出很好的软件，另一些人经过大学和研究生教育仍无法把所学用于企业工作。节目将差异归因于数字原生经验和数字素养基础，而不仅是智力或课程难度。
- 主持人认为，普及数字素养应先于具体编程教育。只有先理解数字世界的基本规律，学习者才更容易形成自主学习和主动解决问题的能力。

### 44:15-58:53：GitHub 替代者与代码托管竞争

- 节目从一个迁移到 Codeberg 的开源项目说起。Codeberg 是在德国注册、由非营利机构维护的开源代码托管平台，支持多语言并拥有真实的活跃项目，因此成为欧洲用户和部分全球项目的选择。
- GitHub 的替代者包括 GitLab、Gitee（码云）以及其他开源代码托管项目。节目提到，一些替代平台不仅提供仓库、Issue、Wiki 和讨论区，还通过云服务、SaaS 或自托管方案形成商业化路径。
- 主持人回顾国内代码托管平台的几轮兴衰：早期平台有的关闭或被收购，华为也曾为大规模内部研发转型采购代码托管平台；美国开始制裁后，国内再次意识到代码托管基础设施的重要性。
- 节目认为，国内平台面临的关键不只是技术，而是如何形成公共服务、国际化和全球开发者网络。仅在 GitHub 对某些用户不可用时填补空白，无法成为真正有吸引力的全球产品。
- 鸿蒙和 OpenEuler 能在码云上托管，开源 Git 平台也已兼容大量 GitHub Actions，被节目视为技术能力已经达到可用水平的证据；下一步的分水岭是能否吸引平台之外的复杂项目，把“可用”变成生态影响力。

### 58:53-01:08:32：群智开发模式与开源基础设施

- GitLink 发布“群智开发模式”白皮书，把软件开发概括为从传统工程模式、开源社区模式走向新的群体智慧协作模式，并把代码托管、流水线、CI/CD 和插件结合在一起。
- 节目对新概念保持审慎，认为软件工业化必须回答工作如何分配、报酬如何发放、质量如何控制等问题。仅发布一份五十至六十页的白皮书，还不能证明这些环节已经真正落地。
- “群智”最初主要服务于学术论文、项目申请等场景，随着开源兴起，才开始被设想为连接高校、工业界和全球协作的更大模式。节目认为，这种扩展有潜力，但需要继续验证其中的协作和收益机制。
- 主持人对 Codeberg 的观察表明，非营利组织、捐赠、国际化、多语言和真实项目可以共同支撑代码托管服务。国内平台如果要形成同等影响力，首先需要明确面向全球开发者提供独立选择的目标。
- 节目最后把问题归结为思路而非单纯技术：代码托管平台不应只在别人无法使用 GitHub 时提供替代，而应让所有不喜欢或不愿依赖 GitHub 的人都愿意主动使用它。

### 01:08:32-01:21:39：Android、AOSP 与鸿蒙的技术层次

- 节目解释 Android 并不是一个单一对象，而是包括商标、AOSP 开源平台、Linux 内核、系统服务、Google Mobile Services（GMS）、应用商店和开发工具等多个层次。GMS 中的推送服务和其他组件并不开源，使用还受 Google 授权体系控制。
- AOSP 还包含设备驱动、系统服务和 Android 应用运行环境。早期 Dalvik 虚拟机带来性能和内存管理问题，后来 ART 通过提前编译和优化改善了运行效率，这也是理解 Android 与原生应用差异的一部分。
- 鸿蒙基于 AOSP 和 Linux 内核中可使用的部分，但华为对驱动和系统服务进行了定制，并开发了对应 GMS 的 HMS。节目认为，华为被限制使用 GMS 后不得不深入掌握 Android 底层，这与只修改界面的“套壳”不是同一个难度。
- 鸿蒙原生应用路线可能减少对 Android 虚拟机的依赖，直接生成系统可运行的代码，从而改善游戏、本地 AI、图形图像和特殊通信模块的性能。节目认为，是否称为“安卓套壳”取决于讨论的是界面、系统服务还是完整运行环境。
- 节目给出的判断是，鸿蒙可以作为独立操作系统存在，同时也是 Android 同源的子生态；小米 HyperOS 也会从共同起点出发逐步形成自己的差异。若外部限制进一步切断 Android 相关组件，鸿蒙生态可能会继续分岔。

### 01:21:39-01:31:16：完整手机生态与多条技术路线

- 节目提醒，手机生态不只有操作系统，还包括硬件、系统服务、开发环境、应用商店、用户群体和开发者。只讨论 SDK、应用分发或某个开源组件，都会把复杂问题过度简化。
- 应用分发本来就是一个已经切片的环节：同一套应用可以针对运营商、硬件厂商、应用商店和网站生成不同安装包。鸿蒙原生应用是否形成真正差异，要看它能否带来独特能力，而不是只增加一个分发渠道。
- 节目认为，华为投入大量人力建设鸿蒙及其生态，持续发布生态报告、吸引企业贡献代码，说明它面对的是替代手机平台的真实商业挑战，而不是简单改名或骗取补贴。
- 讨论最后回到“更多选择”的主题：过去可以直接模仿先行者，未来越来越多的技术需要自己创造。共同基础不代表只有一条正确路线，操作系统和生态也可以在不同方向上发展。

## 核心观点

1. 面对战争和公共事件，应该先区分事实、责任归属与传播立场；舆论阵营的一致口号不能替代对具体证据和责任链的分析。
2. 外部限制会制造短期困难，但也可能迫使产业补齐芯片、软件和生态的完整链条。真正的自主能力来自长期协作和艰苦实现，不是一次新闻带来的“躺赢”。
3. 开源项目的生命力不仅取决于代码是否开放，还取决于接班人、开发者体验、国际化、公共服务和真实项目的持续使用。
4. “开源”“生态”“国产”和“套壳”都不是脱离具体层次就能判断的词。只有拆开内核、系统服务、工具链、分发和用户开发者网络，讨论才有技术意义。
5. 技术发展不只有模仿一条道路。共同使用某些基础组件，并不妨碍后来者通过定制、分岔和新的生态组织方式建立不同的产品路线。
