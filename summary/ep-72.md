# 第 72 期 有组织科研和数字化转型

## 内容摘要

本期从“ChatGPT 变笨了吗”谈起，几位主播用插件解读 GitHub PR 的体验比较 ChatGPT、Claude 和 Google Bard，讨论模型质量评测的困难、模型小型化的意义，以及 OpenAI 在大规模部署和持续优化上的工程能力。Meta 开源 Llama 2 后，话题进一步延伸到开放模型能否成为 AI 领域的基础设施。

节目随后回顾知乎从邀请制的高质量问答社区走向开放注册、流量运营和品牌运营的过程。主播认为，匿名本身不必然破坏社区，真正关键的是内容评价、用户自治、算法设计和平台运营是否共同维护了知识质量；华为内部匿名论坛和大型组织中的信息纠错机制，则说明匿名空间也可以承担重要的反馈功能。

中段解释“有组织科研”的政策背景和现实难题：面向国家重大目标的科研需要跨学科、跨机构和产学研协作，但不能因此消灭自由探索。节目借《为什么伟大不能被计划》的争议，讨论计划、偶然性和科研方向选择之间的关系，主张为长期基础研究保留制度空间，同时对中短期任务加强工程化管理。

最后把数字化转型拆解为一套从数据到价值的方法：先让业务看得见，再通过模型管得住，最后用指标管得好；企业不能把购买信息系统等同于完成转型，应该先诊断自身问题、寻找有价值的应用场景、建立基本模型，再决定需要哪些系统和数据。

## 时间线

### 00:00-14:46：AI 变“笨”了吗与模型小型化

- 一些 ChatGPT 资深用户发现模型重复旧问题、回答质量下降；主播用插件让多个模型解读 GitHub PR，体验上 ChatGPT 最准确，Claude 的结构化表达较好但有些判断偏离，Google Bard 则完全误解了 PR 要解决的问题。
- OpenAI 对相关反馈的解释是：大部分场景经过优化后变好，少数场景会变差。节目认为，模型质量评测本身很难，速度变快也不能简单等同于思考能力下降。
- 大模型正在尝试小型化。更小的模型更容易部署到不同设备，也可能降低训练数据门槛，让数据较少的具体领域获得可用模型；但“每个人手机里都有完整模型”仍未必是必要或近期可行的形态。
- 大规模在线服务可以针对人群、地区和任务持续进行 A/B 测试与局部调整，用户感受到的差异可能来自长期工程迭代，也可能来自特定场景的服务降级。
- 节目认为，OpenAI 的优势不只在算法和模型，也在于把模型部署为大规模外部服务，并在内部研发环境和线上发布环境之间顺畅切换。

### 14:46-24:08：知乎的早期社区与运营转向

- 知乎早期采用邀请制，用户希望认真提问、负责任地回答，并在各个领域形成有专家参与的深度讨论；开放注册后，社区规模扩大，也不可避免地失去部分早期的纯粹性。
- 开放初期曾围绕友善度、活跃度和问题数据进行社区讨论，用户把知乎当作共同建设的知识空间；主播后来认为，平台逐渐把初心让位给 KPI、热闹和事件驱动。
- 节目回顾了运营人员通过提问、邀请、点赞、加关注和推荐等方式制造热点的案例，认为这种暗箱操作破坏了用户对规则和内容质量的信任，也促使早期用户离开。
- 知乎原本可以依靠高质量问题和答案积累知识，再让贡献者提供付费内容；后来的运营导向则让平台更像娱乐社区，答案是否有梗、能否获得点击，逐渐压过了论据和专业性。
- 学生、家长和求职者仍会通过知乎了解学校、老师、实验室和雇主，因此平台上的匿名小作文、品牌宣传和竞争性抹黑会实际影响他人的选择。

### 24:08-35:47：算法治理、品牌运营与匿名功能

- 节目将社区治理方式区分为运营驱动和算法、用户自治驱动，并介绍 Slashdot 通过动态选出高贡献用户组成评议群体，再结合投票权重筛选内容的做法。
- 知乎从高质量问答转向流量内容后，企业和学校开始主动建立品牌账号；平台通过匿名负面内容吸引品牌方来做运营，主播将这种机制形容为一种变相的“绑票”。
- 匿名小作文可以迫使企业回应、建立正面形象，但也让学生和家长难以判断内容是真是假；匿名的取消并不能自动解决平台的内容评价和价值观混乱。
- 主播认为，知乎早期依靠志愿者编辑和专业用户维护内容质量，后来却更多用点击量判断内容优劣，最终偏离了问答社区的本意。

### 35:47-44:23：匿名社区与大型组织的纠错机制

- 匿名空间不必然导致低质量内容。A 岛采用“前台匿名、后台实名”的方式，允许用户使用随机马甲，并发展出接龙式创作；节目认为，结果取决于规则、算法和产品设计。
- 华为内部的“心声社区”也允许员工使用多个马甲，在管理员之外保持相对匿名，让员工能够讨论公司问题；封闭的内部论坛甚至可能暴露一个部门或多层管理中被屏蔽的问题。
- 大型组织层级越多，信息在上传下达中失真越严重，因此需要一个不常用但能在关键时刻发现问题的反馈渠道；主播把它比作最后的纠错手段。
- 维基百科等公益社区也会在影响力扩大后受到利益介入，说明维护内容质量不能只依赖早期理想主义者，更需要持续有效的治理设计。

### 44:23-55:27：什么是有组织科研

- 节目先用“撒胡椒面式科研”描述传统支持方式：高校给青年教师启动经费，国家基金按个人和课题提供普遍性支持，研究者也可以出于好奇心做“优雅而无用”的基础研究。
- 有组织科研的政策背景是中美竞争、国家安全、经济发展和重大技术需求，目标是针对人工智能、芯片等领域形成基础性、原创性或颠覆性成果。
- 论文、项目和 H 指数等评价指标容易诱导研究者在极细的领域里占坑、生产碎片化成果，反而让真正重大的科学问题缺少长期投入。
- 现代科学问题越来越复杂，不能只靠一个人或一两个学科解决，需要系统论、跨学科协作，以及高校和产业界的联合。
- 这种科研模式会改变项目发布、团队构建和评价方式，例如采用“揭榜挂帅”、让企业牵头高校配合，并尝试根据重大任务和长期成效进行评价；它目前更像一个框架和导向，具体落地仍很困难。

### 55:27-01:00:27：重大任务、研究机构与协作组织

- 有组织科研在目标上强调集中支持重点方向，但“集中力量办大事”的组织方式比目标聚焦更难：现代高校组织松散，院系之间、学校之间和产学研之间都可能缺少协作动力。
- 新设的未来技术学院、现代产业学院等机构，可以把不同院系的人才组织起来，并在成立时同时提交任务、人员安排和三到五年的规划。
- 高校跨地区设立研究院，也可以把多个学院的人才与当地企业、行业结合起来，围绕具体产业问题开展研究；关键是机构不能只成为没有实际人员和任务的空壳。
- 新机构必须接受阶段性评估，决定三年、五年后是否继续支持；如果执行中出现“上有政策、下有对策”，制度目标仍可能被消解。

### 01:00:27-01:09:49：《为什么伟大不能被计划》的争议

- 节目讨论《为什么伟大不能被计划》：书中用比尔·盖茨、谷歌和马斯克等案例说明，伟大创造常常出现在无人预先计划的领域，并列举癌症战争、第五代计算机等政府主导项目的失败。
- 主播认为，单靠成功案例堆积，不能证明目标、计划和战略方向没有价值；把偶然性包装成规律，甚至可能让人误以为突破技术壁垒只能靠等待意外发生。
- 另一种更合理的理解是，具体突破可能有偶然性，但国家选择方向、提供资源、组织大量尝试，仍然可以提高成功事件出现的概率。
- DARPA 被用作例子：它允许项目失败，但研究方向并非随意，而是经过选择，并通过多个项目同时下注来获得少数成功；节目将其比作“饱和式轮盘赌”。
- 科研政策既不能迷信单一计划，也不能用“无为而治”否定组织能力。产学研结合以及把成果产业化、产品化，同样是决定科研投入能否产生社会影响的重要环节。

### 01:09:50-01:13:56：自由探索与工程化科研的分工

- 有些科研工作很难被项目化和工程化，尤其是面向未来的自由探索；如果所有人都只追求中短期成果，长期储备和底层突破就会被耗尽。
- 节目建议为自由探索和培养未来科学家保留一部分稳定资源，举例认为可以先保持约 20% 至 30% 的力量，再根据效果逐步调整。
- 剩余的大部分科研任务可以加强工程化管理，在五到十年的周期内持续产出；关键是区分不同类型的科研，不能让所有人都把自己定义成需要长期自由探索的少数人。
- 真正的难点不只是项目管理，而是制度如何让合适的人做合适的事，并为自由探索提供类似长期保障的机制。

### 01:13:56-01:22:33：数字化转型的三步模型

- 节目把数字化转型的本质概括为从数据中挖掘新价值，而不是简单地把原有手工流程搬到计算机或购买一套大厂系统。
- 一套从研发工程治理中总结出的方法是：先“看得见”，把人员、代码提交、服务器压力、编译测试等数据汇总并形成全流程模型。
- 第二步是“管得住”：把模型转化为可执行的规则，例如发现某个开源软件版本存在安全漏洞后，能够阻止整个公司继续使用该版本。
- 第三步是“管得好”：在可见和可控的基础上建立指标体系，逐步判断研发或其他业务过程的好坏；生产制造、城市交通和国家治理也可以采用相同思路。
- 企业购买工具却没有完成转型，往往是因为管理者和员工缺少数字素养。系统只能承载和补充数据，不能替企业自动定义问题、建立模型和选择改进方向。

### 01:22:33-01:30:52：从数据采集到业务价值

- 企业数字化转型的两个关键判断是：数据必须服务于“新价值”，而成败取决于能否找到有创新机会的业务场景。
- 先把所有手工环节都系统化，往往只是增加数据采集和学习成本，并不会立即产生额外价值；如果没有想清楚数据将被用来解决什么问题，信息化容易变成负担。
- 找场景应该询问真正负责管理的人：例如研发负责人可能想知道团队成员的相对效率，以便进行晋升、薪酬和人员安排，而不是先听开发人员决定采集哪些数据。
- 生产型企业可以分别诊断生产、营销和管理环节，先用行业对比和基准测试找出提升空间，再在最有价值的环节引入软件、机器人或 AI。
- 数字化项目应控制早期成本和范围，先验证一个有明确回报的场景；“一窝蜂上数据”并不会自动带来转型。

### 01:30:52-01:33:07：数字素养与转型起点

- 如果企业负责人说不清当前最重要的问题、哪个环节有提升空间以及应该先做什么，就很容易被不同供应商用“数字化转型”包装的系统牵着走。
- 在购买新系统前，应先提升管理者的数字素养，至少能够对企业运营进行基本建模、理解关键指标并区分咨询、诊断和系统实施的先后顺序。
- 更稳妥的顺序是：诊断企业现状，找到改进机会，围绕机会建立数字模型，再决定上哪些信息系统，用系统补齐模型所需要的数据。

## 核心观点

1. 大模型的能力变化不能只凭个别体验或速度判断，模型质量、训练规模、服务部署和持续工程优化需要放在一起评估；开放模型的价值也在于成为更多人可以使用和改造的基础设施。
2. 社区从高质量小圈子走向大众平台后，规模增长并不会自动产生高质量内容；用户自治、算法、运营规则和内容评价机制共同决定社区最终会变成知识平台还是流量娱乐平台。
3. 匿名本身不是治理结论。前台匿名、后台可追溯的设计，既可以支持创作和坦诚反馈，也需要依靠规则、产品功能和管理者维护边界；大型组织尤其需要保留能暴露失真信息的反馈渠道。
4. 有组织科研不应被理解为消灭自由研究，而是把长期自由探索、重大任务和工程化执行区分开，用不同的资源、评价和组织机制支持它们；计划与偶然性可以同时存在。
5. 数字化转型的起点是对业务建立可理解的模型，而不是采购系统。只有先找到数据能够创造新价值的场景，再按“看得见、管得住、管得好”的顺序建设系统，投入才可能形成改进闭环。
