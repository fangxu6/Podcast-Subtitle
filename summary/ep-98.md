# 第98期 新年的开源榜单和大模型

- SRT 条目：571
- 阅读段落：120

## 内容摘要

本期从鸿蒙 Next 的开发者测试和原生应用生态谈起，讨论一个新操作系统在摆脱 Android 依赖时，应该如何处理兼容层、第三方应用迁移和市场信心。节目随后介绍基于 GitHub 与 Gitee 开发者行为数据的 OpenRank 开源榜单，覆盖项目、企业、基金会、国家地区和开发者，并认为把国内平台纳入全球统计，是理解中国开源影响力的重要一步。

节目接着讨论新一年的大模型进展：OpenAI 面临监管、军事用途和竞争压力，Llama 3、智谱 GLM-4 以及本地七十亿参数模型让可选择的产品越来越多。主播认为，今年的进展可能不像上一轮那样带来强烈的“从零到一”冲击，但会让联网模型、本地模型、文件分析和其他能力更加普及。对百度的讨论则集中在战略判断与组织执行之间的落差：它往往启动得早、投入得大，却难以把不同项目和长期资源整合起来。

最后，节目从一个早期在线卖书网站停止服务，讨论技术书籍的时效性、电子阅读、社会化批注、AI 辅助读书和数字出版。纸质书不会立刻消失，但搜索、摘编、迭代、互动和服务等功能会越来越数字化；出版业能否跟上，取决于它是否把书看成持续更新的数字体验，而不只是经过漫长流程制作的一次性物品。

## 时间线

### 00:00-11:51：鸿蒙 Next 的原生生态与迁移成本

- 鸿蒙 Next 已经从路线图进入开发者申请测试阶段，所有开发者可以申请完整环境，学校也开始培养原生鸿蒙开发者，游戏等领域出现合作尝试。
- 目前版本要求 Android 应用重新通过鸿蒙工具链编译，不能直接运行原生 Android 应用。节目认为，这种独立路线有助于摆脱长期跟随 Android 的位置，但会显著增加应用迁移成本。
- 苹果从 Intel 迁移到自研 ARM 芯片时，使用 Rosetta 兼容层让旧应用继续运行，再依靠市场规模推动开发者逐步原生适配；节目以此说明平滑迁移对新生态的重要性。
- 如果微信等主流应用暂时不跟进，缺少兼容层就可能成为硬件销售和第三方厂商决策的“红灯”。鸿蒙最终能否成功，仍要由真实市场和用户口碑验证。
- 生态建设通常需要多年规划，不能把进入开发者测试阶段直接等同于生态已经成熟。

### 11:51-14:48：OpenRank 的数据与指标

- 新一年的开源榜单基于 GitHub 和 Gitee 上的开发者行为数据，包括 Issue、代码提交和 Review 等事件；2023 年 GitHub 记录的事件数据约为 14 亿条。
- OpenRank 借鉴 PageRank 的思路，把仓库、开发者和组织放到关系网络中计算影响力，也可以进一步聚合到企业、国家和地区。
- 今年榜单首次把 Gitee 的数据纳入同一套统计框架，使报告可以同时观察全球平台和国内平台上的项目、人员与企业活动。

### 14:48-23:48：项目、企业、基金会与国家榜单

- 全球项目榜单包含包管理器、Home Assistant、VS Code、PyTorch 等活跃项目；中国项目榜单中，OpenHarmony、openEuler、PaddlePaddle、MindSpore、openGauss 等项目表现突出。
- 企业榜单把项目发起与后续运营归到企业名下，全球前列包括微软、谷歌、亚马逊和华为；中国企业榜单中，华为、阿里、百度、蚂蚁和腾讯等进入前列。
- 基金会榜单把 Linux Foundation 拆分为旗下子基金会，以免其规模直接压过其他对象；Apache 和开放原子基金会因此位居前列。
- 国家和地区榜单中，美国、德国、中国、英国和印度排名靠前；开发者榜单则显示开源参与者来自多个国家，不是单一国家的排名竞赛。

### 23:48-34:48：榜单的意义、可信度与开源趋势

- 过去只看 GitHub，会低估主要把项目放在 Gitee 上的国内企业和开发者；华为此前在 OpenRank 中排名偏低，就与平台数据没有打通有关。
- 这次榜单由第三方团队根据多平台数据制作，报告的价值不只是制造宣传热点，还在于公开统计口径，让项目和企业能够补充遗漏的标签与事件。
- 节目认为，按这套统计口径，Gitee 的活跃仓库总体活跃度已经在 2022 年超过 GitHub；华为在企业榜单中的排名也从 2019 年的第八名持续上升到前列。
- 中国企业在 GitHub 上的 OpenRank 影响力占比从 2015 年的 5.16% 上升到 2023 年的 23.7%，但中美开源整体体量仍约有三倍差距。
- 真正讲好中国开源故事，既需要更多能够站住的底层项目，也需要中立、可复核、能覆盖不同平台的全球统计体系。

### 34:48-45:00：OpenAI 的监管、军事用途与不确定性

- Sam Altman 认为 AI 发展速度会非常快，绝大多数人可能无法及时准备；节目把数字素养普及视为应对这种速度差的必要工作。
- 他还提出应由强力组织监管最强大的 AI。节目认为，主动接受监管可能既是对风险的担忧，也是在降低公众对超前技术的戒心，但其真实动机和长期方向仍不清楚。
- OpenAI 原先“不将技术用于军事”等政策表述被修改，节目同时讨论了其与美国国防部门合作的报道，认为尖端技术很难完全脱离军事用途。
- Altman 在不同场合一方面强调 AI 会快速发展，另一方面又表示它对生活的影响可能没有那么大。主播因此提醒，行业领导者的公开判断也可能受压力、利益和情绪影响，不能直接当成可靠预测。

### 45:00-53:50：Llama 3、GLM-4 与开放竞争

- Meta 围绕 Llama 3 的公开信息显示，训练使用了极大规模的计算资源；节目据此讨论开源模型是否会继续开放，以及社区贡献对模型竞争的作用。
- 节目认为，OpenAI 很难依靠一个长期隐藏的“秘密杀手锏”保持巨大代差，模型方法和有价值的研究思路正在快速扩散到竞争者之间。
- 清华系智谱发布的 GLM-4 可以免付费、免邀请直接使用，主播试用后认为其基础能力已接近 ChatGPT，同时还在搜索、数据分析、代码生成和多模态能力上全面跟进。
- 智谱选择先追平成熟产品，而不是为了差异化而拒绝跟随，被节目视为后发阶段合理的产品策略；免费开放用户入口则有助于快速获得反馈和改进。

### 53:50-01:03:15：本地模型、混合专家与普及化

- 七十亿参数规模的本地模型在性能、内存占用和运行成本之间较为平衡，配备独立显卡的普通笔记本已经可以运行特定领域模型，并在自然语言和代码任务中达到实用水平。
- 混合专家（MoE）通过组合多个模型处理不同子问题，可能获得接近更大模型的效果，但多模型协作会带来更高显存需求和更慢的交互速度。
- 开源社区可以并行尝试不同的模型组合和参数规模，快速筛选出更好的路线；这种大规模共创是传统研发流程不容易达到的速度。
- GLM-4 的文件分析可以完成缺失值检查、统计分析、可视化和探索性数据分析，但面对自由格式文件时仍可能处理不稳定。
- 今年大模型更可能从“令人惊奇的突破”转向更普及、更可达的能力：联网模型、本地模型和文件分析会逐渐成为更多人的工具。

### 01:03:15-01:18:13：百度的战略判断与组织执行

- 百度很早布局搜索、贴吧、网盘、教育、开源、在线开发平台和自动驾驶，也较早进入大模型领域；节目认为其创始人和技术团队的战略眼光并不弱。
- 问题在于公司的项目彼此分散，各自承担细致可执行的 KPI，却缺少把投资、流量、技术和长期目标整合起来的组织机制。
- 百度自动驾驶曾较早获得上路测试机会，但没有像华为那样持续把真实道路数据、模型训练和终端产品迭代连成闭环；外卖、教育、开源投资和文心一言也被放在类似的讨论中。
- 节目把微软投资 OpenAI 作为对照：微软把多个团队调动到一个明确的 AI 战略下，能够把高层判断继续传导到研发、产品和资源配置。
- 百度的问题不一定是看不见机会，而是经常早期投入很猛、后续缺乏长期规划，导致项目在最初势头消退后难以继续推进。

### 01:18:13-01:36:11：在线书店、电子阅读与数字出版

- 一个早期的在线卖书网站停止服务，引发节目对技术书籍未来的讨论。热门技术更新很快，在线文档、源码和搜索往往比翻译出版更及时，因此技术书籍的有效期相对较短。
- 纸质书便于翻阅、标记和沉浸式阅读，电子书则更适合搜索、摘录、整理和重新编排。主播也分享了把数字资料汇总、打印成小册子再阅读的做法。
- 微信读书的月费模式和围绕段落的社会化批注，提供了传统纸书难以实现的讨论层；但批注数量增长后也会出现废话，需要更好的信息筛选和排序。
- AI 可以通过总结和对话帮助读者处理整本书，实用主义的阅读会因此减少对纸张和实体书的依赖，但纸质书的阅读体验和收藏价值不会立刻消失。
- 出版业一方面仍有流程缓慢、审查繁复和缺少技术力量的问题，另一方面已经出现把教材数字化、建设互动内容和运营教师社群的先进实践。未来出版可能更像发布一个持续迭代的数字应用，而不是完成一次印刷就结束。

## 核心观点

1. 新技术生态的难点不只在底层技术，还在迁移路径、兼容策略、第三方参与和用户规模；一次发布或一次测试不能等同于生态成熟。
2. 开源影响力需要可解释、可复核的数据体系。合并不同平台的统计，既能减少结构性遗漏，也能让争论从印象和自我贬低回到证据。
3. 大模型竞争正在从单一模型的惊人能力，扩展到开放程度、工程整合、本地运行、工具调用、社区共创和用户反馈。
4. 企业能否持续抓住技术机会，取决于战略能否穿透组织边界，转化为长期投入、跨团队协作和真实产品迭代。
5. 阅读和出版的数字化不只是把纸书转换成文件，还包括搜索、批注、协作、更新、推荐和与 AI 对话等新的内容服务。
