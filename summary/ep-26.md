# 第 26 期 Evil.js 是真的邪恶

- 来源：`transcript-site/episodes/ep-26.html`
- 时长：01:29:56
- SRT 条目：658
- 阅读段落：118

## 内容摘要

节目先回应听友关于学位论文获取方式的问题，比较国外大学主动公开论文与国内主要依赖知网、CAJ 格式的现状。讨论认为，论文开放获取既能促进知识传播，也能成为学校和研究者展示成果的方式；国内的障碍更多来自开放意识、学校数字基础设施和既有垄断机制，而不只是技术成本。知识可以商业化，但基础的检索和阅读不应被封闭格式与单一渠道过度限制。

随后从俄罗斯汽车爆炸事件及其网络舆论谈到认知战，提醒听众不要因为一条未经核实的说法获得大量转发和点赞，就把它当成事实。主体话题是 `Evil.js`：项目用随机、周期性的恶意行为给软件埋毒，虽然以反 996 为动机，却把反对违法加班和破坏软件供应链混为一谈。节目进一步讨论 996.ICU、开源许可证的中立边界，以及企业在依赖追踪、权限管理和人员离职时面临的供应链风险。

后半段把话题推进到更广义的信息安全：长工时可能掩盖管理和决策效率问题，动态语言让恶意行为更难分析，Rust 等语言则试图用更强的编译期约束提高可靠性。数据泄露后的责任推诿、汽车工程模式未修改默认密码、电厂控制网络和智能家居的联网风险，以及区块链函数重入漏洞，都说明安全不能只交给少数安全专家，而需要进入系统设计、编程教育、软件治理和全行业的日常实践。

## 时间线

### 00:00-20:36：论文开放获取与 CAJ 格式

- 节目回应听友关于国外大学公开学位论文的问题：一些海外高校会集中收集并免费发布各学院论文，这既方便学术交流，也能展示学校和研究者的成果。
- 国内论文通常集中在知网等统一渠道，学校主动建设论文公开平台的案例较少。节目认为，原因包括开放数据意识较晚、学校数字基础设施和持续运营能力不足，以及历史形成的渠道垄断。
- CAJ 源于互联网尚未普及时期的学术光盘发行体系，后来随着知网等平台延续下来。它需要专门的阅读器，阅读、复制、检索和兼容性体验都不如 PDF 等通用格式。
- 节目区分了合理商业化与信息垄断：基础检索和阅读可以尽量开放，附加服务再收费；知识传播和科技人才培养不应被封闭格式人为抬高门槛。

### 20:36-27:57：俄罗斯事件与网络认知战

- 节目提到莫斯科郊区的一起汽车爆炸事件：一名俄罗斯政治思想家的女儿遇害，事件动机和真相在当时仍未完全确认。
- 相关网络账号迅速传播一条关于死者曾发表极端言论的说法，但主播无法从原文和上下文核实，认为它可能是截取、改写或凭空制造的叙事。
- 网络转发量、点赞量和阵营立场会制造“很多人都这么说，所以应该是真的”的错觉；这类舆论战可以迅速改变人们对事实和历史的认知。
- 节目用一则停车被拖走的舆论反转案例说明，公共讨论中有人会把“停了几分钟”夸大或缩小成有利于自己的版本。涉及切身利益或关键判断时，应先保留怀疑并等待核实。

### 27:58-41:45：Evil.js、开源投毒与许可证边界

- `Evil.js` 的 README 明示可把项目偷偷引入公司代码，并通过特定数字、星期或概率触发异常行为，例如让函数返回错误或偶尔丢失数据；项目还试图用“后果自负”推卸责任。
- 这种做法利用动态语言修改全局基础库行为的能力，把恶意代码隐藏在依赖中，甚至可以设计成很久才触发，使企业难以定位损失来源。
- 节目肯定 996.ICU 反对制度化、无偿和违反劳动法的强制加班，但认为以恶意代码投毒来反击公司已经越过了正当抗议的边界。
- 反 996 许可证不能因为使用者属于某类公司，或因为软件被用于某种领域，就限制其使用；这与开源定义要求许可证不歧视个人、团体和使用领域的原则冲突。
- 开源项目可以通过社会和法律机制反对不合理制度，但不应让许可证或代码代替人类社会作道德审判，更不能以正义之名主动制造安全风险。

### 41:47-51:44：软件供应链、权限管理与 996 运动

- 企业需要通过依赖追踪、安全扫描和供应链治理识别投毒风险；真正困难的是恶意包可能换名字、只修改一处行为，甚至把代码藏在字符串和混淆逻辑中。
- 开源开发改变了企业的软件边界。员工转岗或离职后，如果企业账号、代码托管平台和开源项目权限没有联动收回，原成员可能仍能修改关键仓库，而组织内部甚至没人知道这项权限存在。
- 节目区分了“所有加班都不合理”和“制度化违反劳动法的 996”：前者存在现实灰度，后者是需要明确反对的对象。
- 996.ICU 由程序员自发传播后引发社会关注，节目认为它虽然没有一步解决问题，却客观促使不少公司开始收敛，并重新讨论工作制度。

### 51:44-58:20：从堆工时到提高组织效率

- 节目反驳把 996 当作企业竞争优势的看法，认为用超额工时填补决策和规划上的漏洞，本质上是管理失能，而不是员工效率更高。
- 当企业无法衡量团队真实产出时，管理者容易退回到观察员工在办公室停留多久这种形式化指标；但高强度工作时长不等于有效工作时长。
- 通过同时做多个未经充分判断的方案，再依靠人力和时间覆盖浪费，是一种昂贵的试错方式。行业从高速扩张转向稳健经营后，需要更重视目标、决策、协作和每个人的实际产出。
- 节目认为改变工作文化不会一蹴而就，但重要变化是越来越多企业开始承认问题，并尝试从堆人堆时间转向提高效率。

### 58:21-01:02:58：恶意代码的法律与治理难题

- 节目认为，针对一般计算机系统的恶意投毒，现有法律在行为定性、损失举证和责任边界上仍不够清晰；现有网络安全和个人信息保护规则也未必能覆盖所有类似场景。
- `Evil.js` 的危险不只是一次恶作剧，而是把制造隐蔽恶意行为的思路和方法公开给更多人，降低了实施破坏的门槛。
- 企业仍然无法简单停用 JavaScript 等动态语言，但可以考虑依赖治理、静态分析、AST 检查和对运行场景的限制；经过混淆、字符串拼接或动态执行后，单看原始代码并不够。
- 节目把软件治理与法律、权限和工程流程联系起来，认为技术手段需要和明确的责任制度一起建立，而不能只寄希望于开发者自觉。

### 01:02:59-01:09:33：Rust、C++ 与编程语言的取舍

- 随着软件进入更多设备和基础设施，可靠性、可移植性、内存管理和安全性变得更重要；程序员能力差异也会放大底层语言的风险。
- C++ 几乎可以做任何事情，但允许质量不高的代码编译运行；Rust 试图把更多约束前移到编译器，让不满足安全条件的代码更难通过，从而提高底层软件的可靠性门槛。
- Rust 的取舍是更严格、更难掌握，很多程序员并不喜欢这种接近“完美”的约束。节目认为，语言是否成功取决于真实场景、开发者接受度和可靠性收益之间的平衡。
- 继承等面向对象概念也被当作“易于入门的抽象”讨论：它能帮助初学者理解复用和特化，但深入后往往会发现接口、组合和消息机制可以解决很多同类问题。

### 01:09:33-01:19:35：数据泄露、默认密码与联网设备

- 面对上海近期的数据泄露事件，相关机构的第一反应被描述为急于声明“不是我们泄露的”。节目认为，数据管理者即使尚未确认事故原因，也应先说明影响范围、响应措施和自身责任，而不是只做责任切割。
- 一辆现代混合动力汽车的工程模式使用了官方文档中的默认密码，车主因此进入工程界面并尝试改造系统。节目指出，出厂调试密码未被修改是工业设备中很常见的安全缺陷。
- 过去设备未联网时，默认密码的影响可能被物理边界限制；如今设备、控制系统和服务不断联网，原本局部的疏忽可能扩大为远程攻击入口。
- 电厂控制网络的案例说明，外部网络一旦通过中控系统触达工业设备，就可能影响发电机等核心参数；关键设备仍需依靠物理隔离和独立的安全边界，不能只依赖软件权限。

### 01:19:35-01:29:56：智能化便利、函数重入与安全教育

- 智能家居把灯、电器、门窗和其他设备集中到手机控制，便利背后却是更多联网设备、供应商和潜在故障点；安全能力不足的供应商同样可能造成风险。
- 节目以区块链项目 The DAO 的函数重入漏洞为例：攻击者可以在余额更新前重新进入函数，打破“转账和扣减余额必须同时完成”的假设，反复取款造成资产损失。
- 信息安全与普通编程能力并不等价。开发者需要理解异常路径、攻击者行为和系统边界，而不仅是让正常流程顺利执行；安全也应进入操作系统、编译器、语言设计、测试和软件治理。
- 学校课程中安全常被作为附加内容，企业则往往要等到遭受攻击和损失后才真正重视。节目建议使用已经修复、可以公开分析的事故案例进行教育，让开发者和管理者持续看到“安全事故现场”。
- 节目最后强调，信息安全不只是安全公司的职责，而是整个软件行业都需要提升的能力和意识。

## 核心观点

1. 知识传播既需要可持续的商业服务，也需要开放、通用和低门槛的基础访问；封闭格式与单一渠道容易把公共知识变成信息垄断。
2. 反对违法的 996 制度与向软件中植入恶意代码是两件事；正当的社会诉求不能成为破坏供应链、伤害无辜使用者的理由。
3. 开源带来协作效率，也带来依赖、权限和人员变更的治理责任。企业必须把代码托管、账号权限和人员生命周期纳入同一套安全边界。
4. 长时间出现在办公室不等于高产出。用工时掩盖低效决策和组织管理问题，只会把浪费转嫁给员工；成熟企业需要转向更可衡量的效率和质量。
5. 安全应当成为系统设计、编程语言、教育、测试和软件治理的一等约束，而不是事故发生后才补上的附加功能。
