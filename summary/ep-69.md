# 第 69 期 工程思维与社群教育

## 内容摘要

本期从几项法律和政策话题开始，讨论《无障碍环境建设法》如何把物理空间无障碍延伸到信息交流、数字适老化和公共服务；随后分析知识产权保护与反垄断之间的平衡，以及美国最高法院围绕高校招生和其他政策作出的保守派裁决。节目反复强调，制度设计需要同时考虑公平、创新、竞争和实际执行，而不能只看单一价值。

节目中段分享苏州装备数字化研讨会的见闻，重点讨论用 Julia 等开放生态替代 MATLAB 的科学计算和仿真建模能力。替代一个工业软件并不只是重写程序，还要解决兼容性、模型工具、行业经验、教育推广、标准化、开源协作和商业服务等生态问题。

后半段回应听友关于工程经验不足的提问，回顾编程从语句、函数、对象、模块到包和脚手架的抽象粒度演进，并把工程思维概括为可协同、可管理、可复用。节目认为，学校课程负责系统地培养基础能力，真实的开源项目和社群则可以补足长期协作、维护和实践经验，形成一种连接教育与有价值软件工作的社会化培养方式。

## 时间线

### 00:00-12:45：无障碍建设与数字适老化

- 节目从新通过的《无障碍环境建设法》谈起，以杭州步行街入口根据轮椅通行自动放下隔离柱的设施，说明无障碍建设不仅是规范要求，也需要具体的工程设计。
- 法律专门涉及无障碍信息交流，包括老年人和残障人士使用手机、阅读内容，以及电视字幕、手语新闻、盲文和电子无障碍格式等安排。
- 节目指出，老年人面对的数字障碍不只是不会操作，还包括“手机中毒”“内存不足”等诱导性弹窗和恐吓式信息。数字环境本身也应减少欺骗、误导和不必要的复杂度。
- 政府层面的重视已经进入法律和政策，但商业产品跟进较慢。节目提出由手机厂商提供更清晰的适老模式，并建立国家认可的助老、反诈和公共服务入口，降低老人辨别可信服务的成本。

### 12:45-23:54：知识产权保护与反垄断

- 市场监管总局关于禁止滥用知识产权排除、限制竞争的规定，被用来说明知识产权保护和反垄断都是正当目标，但需要避免大型平台用专利布局封锁初创企业的创新空间。
- 节目区分了专利流氓与大公司之间的“专利核战争”：前者靠专利诉讼获利，后者则通过互相建立专利壁垒来保持竞争平衡，两者都可能偏离专利制度鼓励创新的初衷。
- FreeBSD 在 20 世纪 90 年代遭遇专利诉讼、被迫重写代码的经历，被作为开源项目受知识产权纠纷牵制的例子；同期 Linux 的发展则意外获得了更多空间。
- 高校专利商业化也会带来科研人员、学校和企业之间的收益分配与技术发展纠纷。反垄断治理不一定能立即消除巨头，更现实的路径是逐步规训其行为、释放部分利益并改善行业生态。

### 23:54-37:28：美国高校招生裁决与政治撕裂

- 节目讨论美国最高法院以六比三裁定哈佛大学和北卡大学采用种族平衡招生政策违宪。争议的背景是平权政策如何回应黑人历史上的不公，同时又是否对华人和其他亚裔申请者造成新的不公平。
- 嘉宾认为，华人群体关心的不只是族裔政策，也包括子女教育机会和税收。美国华人在政治选择上可能偏向保守派，未必与其在其他议题上的自由派倾向一致。
- 同期讨论的另外两个裁决涉及拜登政府的大学生贷款减免政策，以及拒绝为 LGBTQ+ 群体提供服务的网站是否受到言论自由保护。这些判决被放在美国最高法院保守派占优势、两党对立加剧的背景下理解。
- 判决可以暂时阻止高校跟随某种招生风潮，却不能一次解决美国社会的种族、阶层和政治冲突。节目也提醒，对华人是否最终受益的判断仍需要等待更多具体政策和后续分析。

### 37:28-49:49：MATLAB 替代与工业软件需求

- 苏州装备数字化研讨会聚焦“模型与数据驱动的工业智能化”，其中一个现实需求是为高校、军工和重工业相关场景寻找 MATLAB 的国产替代方案。
- MATLAB 在国内高校中长期被低成本甚至无成本地使用，但企业和专业机构购买正版时价格很高。外部限制使部分学校和行业无法继续依赖原有软件，也让替代成为刚需。
- 节目把 MATLAB 的能力分成科学计算环境和仿真建模两部分。Julia 具有开放、高性能和适合数值计算等特点，可以尝试承接矩阵运算、微积分、可视化以及相关工具箱的能力。
- 工业软件的难点在于长期项目经验和实际应用积累。航空航天、车辆和轨道交通等领域还需要仿真、信号控制、设计、维护和数据分析，不能把替代理解成简单更换一门编程语言。

### 49:49-59:04：从软件替代到开放生态

- Julia 相关团队希望逐步替代 MATLAB 的工具箱和行业解决方案，并将科学计算平台转向 Web 和云端；Modelica 等统一建模环境则尝试覆盖机械、电子、控制等跨学科的数字孪生和仿真需求。
- 国内高校正在通过教育项目推广国产科学计算软件。专业课程、出版社和教育部门的合作，可以让学生在形成软件习惯之前就接触替代工具。
- EDA 等与生产线和行业标准紧密绑定的软件更难替代；相比之下，MATLAB 属于相对通用的工具，如果能兼容既有语法和文件，迁移过程会平缓一些。节目提到，已有方案尝试直接运行 MATLAB 的 `M` 文件或将其解释为 Julia。
- MATLAB 代表的不是一个孤立软件，而是完整的语言、工具箱、模型、用户和服务生态。成功的国产替代需要基金会、学校、企业和开源社区共同建设，并在标准化、社区活跃度和商业收益之间取得平衡。

### 59:04-01:08:39：编程抽象与工程思维的形成

- 听友提到，实验室新人常停留在“写一个文件、运行一次、得到结果”的课程作业模式，而真实项目会使用包管理、脚手架、编译、测试、持续集成和发布等工程工具链。
- 软件开发的抽象尺度从语句和函数，逐步扩展到对象、模块、可复用组件、包和完整工程。现代语言通常把依赖管理和项目结构纳入工具链，让复用成为默认能力。
- Ruby on Rails 的“约定大于配置”和脚手架，被用来说明共同规范如何减少配置和协作成本。软件越复杂，越需要在更大的颗粒度上理解系统，而不是逐项手工掌握所有细节。
- 学习软件工程不能只讲当前技术的用法，还应讲清从软件危机、`goto`、结构化编程、模块化到面向对象的演进历史。理解“为什么这样设计”，比只记住最终规则更有助于形成工程判断。

### 01:08:40-01:19:38：工程思维与软件工程教育

- 节目把工程思维的核心目标概括为可协同、可管理、可复用：工作要能交接和共同完成，结果要能验证和维护，代码与项目经验要能在以后继续使用。
- 初学者如果只写一个文件就能解决问题，很难感受到文档、测试、版本管理、目录结构和协作规范的必要性。工程方法往往要等规模和维护成本出现后，才真正显出价值。
- 学校课程偏爱单文件作业和刷题，是因为它们容易布置、评测和批改，但这种模式很难训练持续数月或数年的真实项目协作。课程之间缺少贯穿多个学期的项目，也进一步削弱了工程经验的积累。
- 节目提出把系统性的思维能力放进课程，把探索、创造、尝试和纠错等难以只靠讲授掌握的能力交给真实项目训练；开源项目可以成为连接课堂和工程实践的载体。

### 01:19:38-01:31:35：开源项目与社群化教育

- 社群化教育能够把快速变化的行业经验总结成可学习、可复制的实践，但开源社区的 code review 也存在不系统、靠偶然触发以及对新人不友好等问题，不能把自然形成的社区现象直接等同于完整教育。
- 真实项目还必须有合适的进入门槛。直接让初学者参与规模庞大的 Linux 等项目会造成挫败，因此更适合建立包含入门、进阶、Web、文档和测试等不同类型项目的项目库。
- 一个可行的模式是由社会上的基金会或社区引入优秀开源项目，大学生按水平参与长期开发，助教负责说明项目结构、环境、工作流程和求助渠道，资深工程师提供真实项目中的指导。
- 这种方式不必立即改造整个大学课程体系，却能让学生在大学期间获得多年协作、维护和复用经验，也可能为项目方提供稳定的人才和外包池，形成教育与软件工作的桥梁。

## 核心观点

1. 无障碍建设必须同时覆盖物理空间、信息交流和数字产品设计，不能把老人和残障人士遇到的困难简单归因于用户能力不足。
2. 知识产权保护的目标是鼓励创新，而不是让专利布局、专利诉讼或平台地位固化竞争；反垄断需要在保护发明人收益和保持开放使用之间寻找平衡。
3. 工业软件替代的对象是一个生态系统。兼容性、工具链、行业模型、教育推广、开源协作和商业服务缺一不可。
4. 工程思维随着软件规模增长而产生，核心是让工作可协同、可管理、可复用；理解技术演进的历史，有助于理解工程规则背后的动机。
5. 软件工程教育需要把课程中的系统性训练与真实项目中的长期实践结合起来，开源社群可以成为学校、企业和学习者之间的连接层。
