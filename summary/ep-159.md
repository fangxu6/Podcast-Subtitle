## 内容摘要

本期先继续讨论关税战的后续，重点转向信息传播中的认知战、越南和日本的谈判姿态，以及中美之间可能出现的技术与信息脱钩。节目还讨论马斯克在政治事务、特斯拉经营和自动驾驶方向之间的矛盾，并认为他的政治投入已经影响了企业创新和个人进退。

随后节目讨论 OpenAI 进入 AI 编程领域，以及基础模型能力迭代放缓后，行业会不会从追逐更大模型转向挖掘现有能力。围绕“AI 的下半场”，节目认为未来需要更能衡量学习、推理等关键能力的 benchmark，而不是继续依赖容易刷榜的机械测试。

后半段从 Agent 框架选型谈到开放科学，强调技术选择必须通过小规模原型和实际任务验证，并综合需求适配度、技术先进性、采用成本和长期支持。最后推荐《永远的丁丁》和《世上为什么要有图书馆》，分别介绍丁丁历险记的创作历程，以及一位挂职干部建设西安碑林区图书馆的经历。

## 时间线

### 00:00-13:13：关税战后的认知战与媒体叙事

- 节目认为关税战开始进入信息传播和舆论引导阶段，网上出现了大量带有明确方向的传闻，需要区分新闻事实、标题剪裁和情绪化解读。
- 越南提出同时把对美关税和美国对越关税降到零，被节目认为是防守反击式的正常谈判方案；但传播中常被简化成“越南投降”或“中国被孤立”。
- 美国对中国商品“245% 关税”的说法也需要按具体品类拆分，节目指出其中包含原有税率和多次加征，并非所有商品统一适用同一税率。
- 节目以日本面对美国汽车和农业关税的反应为例，认为日本有自身难以让步的利益，不应仅凭与美国谈判就判断其已经站到美国一边。
- 节目提醒，看理想等媒体内容既有值得参考的节目，也有带编辑判断的新闻栏目；听众应保留甄别意识，不能因为平台整体有好内容就放弃对具体报道的判断。

### 13:13-22:52：中美对抗、GitHub 与技术脱钩

- 节目把中美关系描述为在不发生热战的情况下，已经进入极其激烈的对抗状态，并认为未来可能出现更明显的战时管制和信息管理。
- GitHub 曾短时间限制中国 IP 访问，随后解释为误操作。节目认为，即使这确实是测试或误操作，也说明美国企业具备随时改变访问规则的能力，不能只相信平台本身而忽略其背后的政府政策。
- 节目将 GitHub 访问限制与英伟达芯片出口限制放在同一逻辑下观察：软件服务和实体芯片都可能成为脱钩工具，只是实体硬件更容易被监管和封锁。
- 对于中国开发者通过代理访问 GitHub 的现实情况，节目认为技术封锁未必能立刻达到预期效果，但相关动作至少表达了收紧和施压的姿态。
- 关税、芯片、代码平台和信息流动被节目视为重构世界贸易、金融、知识与技术秩序的一部分，普通用户需要为这种不确定性做好准备。

### 22:52-34:16：特朗普团队与马斯克的两难处境

- 节目用“做数学卷子”比喻特朗普团队的施政状态：每个问题都先写下一个方案，尝试后发现困难，再回头处理前面的题目，很多目标并未真正完成。
- DOGE 最初提出大幅削减政府开支，目标金额后来不断下调；节目认为，削减预算、揭露腐败等行动在遇到制度和利益阻力后，推进速度明显放缓。
- 马斯克可能对特斯拉的日常运营和缺少技术挑战的工作失去兴趣，但节目也认为媒体报道可能带有制造恐慌的倾向，不能简单理解为他已经放弃造车。
- 马斯克更关注完全自动驾驶和 Robotaxi 等高难度方向，而职业经理人更重视稳定经营和持续盈利，这种矛盾类似创始人追求突破与管理团队追求商业确定性的冲突。
- 进入政治领域让马斯克难以同时投入特斯拉。退出企业相对容易，退出政治则可能遭遇更多报复和利益纠缠；节目认为他正处在进退两难的状态。

### 34:16-47:57：OpenAI Codex 与 AI 编程的现实边界

- OpenAI 发布了命令行形态的 Codex，并传出可能收购 Windsurf 的消息。节目将其视为 OpenAI 强势进入 AI 编程领域的信号，并把市场上的工具分为集成式 IDE、编辑器插件和命令行开源工具几类。
- 节目成员的实际经验是，AI 编程工具经过早期广泛尝试后，往往会稳定在少数几个可靠场景；复杂文件架构修改和需要设计判断的任务仍然不适合完全交给 AI。
- 已有清晰抽象和示例实现时，AI 更擅长阅读代码并依葫芦画瓢。例如先写好一种向量数据库实现，再让模型仿照公共接口补充其他实现，效果通常比让它从零设计框架更好。
- 工具自动运行代码、把结果重新放回上下文并继续修正，确实能提高效率，但节目不认为 MCP 等扩展能力本身就是决定性突破，许多功能更接近锦上添花。
- 节目认为，AI 编程工具不应把“代替人写出完整、正确且可维护的代码”作为近期唯一目标，更现实的方向是最大限度提高程序员生产力。

### 47:57-01:04:04：AI 的“下半场”与 benchmark

- 节目讨论一篇关于 AI “下半场”的文章，认为它关注的不是简单地提出一个新任务，而是寻找能够衡量 AI 关键能力、并反过来牵引技术发展的新 benchmark。
- 现有测试多用人类题目和标准答案比较模型表现，但当前 AI 并不按照人类的方式解决问题，因此这类测试可以衡量结果，却未必能说明模型的学习和推理能力如何形成。
- 节目认为，学习、信息获取、分析资料和从已知推出未知的推理，可能是 AI 接近通用智能时需要重点提升的能力；benchmark 也应更细致地刻画这些能力。
- 节目用游戏地图比喻当前阶段：行业已经打开了一大片可探索区域，却还没找到通往下一张地图的关键入口。与有限的游戏世界不同，AI 技术探索的可能性几乎无法穷尽。
- 目前的 benchmark 可以通过不断加难来追赶模型能力，但仍很难告诉研究者下一步最有价值的方向。节目因此认为，真正的难题是先定义机器智能，再决定应该测量什么，而不是让评测反过来决定智能是什么。

### 01:04:04-01:22:17：Agent 框架与技术选型方法

- 不同 Agent 框架通常都提供模型适配、工具调用、系统提示词配置和多 Agent 编排，但各自侧重不同：有的强调简单快速和预置工具，有的突出结构化数据校验、日志和实时监控。
- 技术选型不能只看框架名气或最新程度。团队应先让 Hello World 和小型 Demo 跑起来，把真实业务中的关键场景缩小后进行比较，而不是完全依赖宣传、文档或下属汇报。
- 节目提出四个选型维度：需求适配度、技术先进性、采用成本和长期支持。最终需要在四者之间取得平衡，不能因为某一项突出就忽略其他风险。
- 对重要项目，推荐提前搭建规模约为正式产品五分之一到十分之一的验证环境，让不同小组用候选方案完成核心功能，从而尽早暴露选型问题。
- 技术偏好和“品味”会影响采用成本，但使用者也应意识到那只是偏好；年轻时在小项目中多尝试新技术没有问题，项目规模和风险增大后则需要逐渐收敛。
- 软件架构师无法速成。学生可以为了学习和求职尝试新技术，但在真实工作中不能只面向简历编程，也不能把生产系统当作试验场。

### 01:22:17-01:32:42：开放科学与人工智能

- 《开放科学》由之江实验室智能社会治理实验室相关团队编写，关注人工智能时代科学、技术与人文如何深度结合，以及技术对社会治理带来的挑战。
- 节目介绍开放科学的基本方向：让更多人公开获取、使用和重复利用科学知识，促进科学合作与信息共享，并向传统科学界之外的社会参与者开放科学知识的创造、评估和传播。
- 书中把 AI 时代的开放科学分为开放模型、开放数据、开放算力和开放设施等研究要素，同时讨论政策治理、技术治理、标准治理、文化培养和全流程评价。
- 节目认为，开放模型、数据、代码和算力等问题仍处于发展中，书中的技术细节未必都足够深入，但它提供了一个系统认识开放科学及其治理问题的框架。
- 开放出版、开放教育和开放案例等实践，可以把开源精神从代码共享扩展到科学协作和社会共识。

### 01:32:42-01:43:09：《永远的丁丁》

- 《永远的丁丁：丁丁历险记创作历程》介绍比利时漫画家埃尔热从 20 世纪 20 年代到 70 年代创作的丁丁系列。丁丁是一名记者，与小狗白雪一起在世界各地经历冒险。
- 丁丁历险记涵盖战争、海盗、印第安人、登月等不同题材，兼有动作、推理、幽默和科幻元素。节目认为，它让孩子像旅行一样接触不同国家、民族和风土人情。
- “蓝莲花”是与中国关系密切的一部作品，埃尔热从华人朋友张充仁那里了解中国，并以抗日战争为背景创作了这部作品。节目认为它是全系列中完成度很高的一篇。
- 书中也提到《丁丁在苏联》带有当时欧洲社会对苏联的偏见，埃尔热后来对此感到后悔，并将这部作品视为自己的警示。
- 推荐从《永远的丁丁》了解作品和作者，再按兴趣挑选漫画阅读；节目还怀念早期纸张结实、印刷质量较好的小人书版本，并认为丁丁适合儿童阅读。

### 01:43:09-01:55:44：《世上为什么要有图书馆》

- 《世上为什么要有图书馆》记录作者杨树秋挂职期间主持西安碑林区图书馆建设的经历。一本关于图书馆开馆的网络文章先引发传播，随后又引来内部压力和媒体关注。
- 节目重点介绍图书馆采购中的“馆配书籍”问题：如果只追求数量，采购方可以用很低的折扣大量购入质量和版本都不理想的书；作者则通过各领域朋友推荐书单，试图为读者选择更好的书，即使采购成本更高。
- 书的朗读版还穿插西安和陕西的风土人情、美食、民歌和朋友演唱，使图书馆建设的流水账之外增加了地方文化和人物的质感。
- 图书馆开馆后的章节转向不同读者：盲人如何在听书和触摸盲文之间选择，书法爱好者如何寻找字帖，儿童需要哪些读物，以及专业人士如何推荐各自领域的书。
- 节目认为，图书馆不只是堆放书籍的公共设施，也应理解读者需求、提供好的选书和阅读体验；推荐通过看理想或微信读书收听作者朗读版。

## 核心观点

1. 复杂国际事件中的新闻、政策和舆论应分层判断，不能把谈判、反制和传播中的简化标题直接当成完整事实。
2. AI 编程的近期价值在于提高人的生产力，尤其适合阅读代码、补全已有结构和处理局部任务；架构设计与复杂问题仍需要人主导。
3. 评测不只是给模型排名，也应帮助研究者识别学习、推理等关键能力；如果 benchmark 无法牵引技术方向，就只能作为有限的结果参考。
4. 技术选型需要真实原型、可比较的实验环境和多维度权衡，不能由追新、名气或个人偏好单独决定。
5. 开放科学把开放模型、数据、代码、算力和教育放进同一个协作框架，公共机构和图书馆同样需要以实际用户和知识传播质量为中心。
