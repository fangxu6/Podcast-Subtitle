# 第 44 期 再见 2022，你好 2023！

## 内容摘要

本期首先讨论《中共中央 国务院关于构建数据基础制度更好发挥数据要素作用的意见》。节目认为，数据已经成为重要的生产要素，也可能进一步成为可交易的商品，因此数据产权、流通交易、收益分配和安全治理不能拆开处理。要实现“可用、可流通、可追溯”，还需要对数据和元数据进行分类、建立标准目录、追踪来源与流通，并把隐私保护和安全治理作为数据商品化的基础。这个问题同时涉及技术、经济、法律和政治，不能只由某一个专业单独解决。

随后节目从 GitHub 的开发者增长谈到印度在互联网和软件领域的崛起。节目引用的年度数据中，新增开发者来自印度的比例明显高于中国；嘉宾认为，这不能被简单解释为两国竞争结果，而与印度所处的发展阶段、人口规模、软件产业扩张、教育和人才流动有关。印度正在从人力资源外包逐步走向制造业、互联网产品和本土软件产业，未来有较长的发展窗口，但政治选择、基础设施和产业稳定性仍然是不确定因素。

中段讨论开源领域的知识工程。嘉宾希望把开源作为社会学、经济学、历史学和法律等多个学科共同研究的对象，逐步建立协作式维基、开源书籍和知识图谱。Markdown、版本控制、双向链接和自动生成幻灯片，可以把知识点、书籍、课程和博客连接成同一个内容网络；但从信息集合走向真正的知识库，需要处理实体统一、关系抽取和人工标注。最后，三位嘉宾展望 2023 年，希望继续推进开源数据、全民计算机科学教育、面向普通人的编程科普、主题协作写作和听友互动。

## 时间线

### 00:00-09:49：数据基础制度与数据要素

- 节目讨论中共中央、国务院发布的《关于构建数据基础制度更好发挥数据要素作用的意见》，认为它的重要信号是把数据明确放在生产要素的位置上，并开始系统讨论数据产权、交易和收益分配。
- 数据的产权、流通交易、收益分配和安全治理是一个整体。文件提出数据应当可用、可流通、可追溯，这背后需要一套强大的数据管理能力。
- 数据管理不能只停留在技术层面。数据从产生开始就需要建立分类目录和标准信息头，说明其中包含哪些个人隐私、敏感字段和其他关键要素，并据此决定保存、共享和交易的权限。
- 数据要素同时具有技术、经济和法律属性。技术人员需要理解制度与社会问题，经济和法律领域也需要理解数据的技术特征，才能制定可执行的细则。

### 09:50-15:27：数据商品化与安全基础

- 节目回顾早期评估互联网企业时已经把数据价值纳入企业估值，认为数据不仅是生产要素，也可能成为商品；但商品化必须建立在安全、隐私和可信追溯之上。
- 关于政治与经济关系的讨论指出，市场并不是脱离制度、可以独立运行的自然存在。数据交易也不可能只追求收益，必然受到政治、公共治理和权力边界的影响。
- 只有先完成分级保护、来源追踪和流通记录，数据交易才有可能扩大规模。节目因此看好标准数据、安全治理和相关基础设施方向。
- 嘉宾还提到正在参与开源元数据标准工作，认为民间实践、产业力量和具有公信力的标准制定机构需要结合起来，才可能让标准真正产生约束力和普遍采用的效果。

### 15:28-24:58：GitHub 增长与印度开发者

- 节目从开源年度报告谈到 GitHub 的增长：平台用户从数千万增长到约 9,400 万，最近一年新增开发者约 1,600 万，其中印度占 32.4%，中国占 15.6%，巴西占 11.6%。
- 这些数字不能直接等同于某个国家的软件实力排名。GitHub 上既有开源贡献者，也有只是使用软件包的开发者；统计结果还受到人口、产业阶段和新用户进入速度的影响。
- 嘉宾根据参与 Google Summer of Code、OSPP 等项目的经验，认为印度学生在开源项目中的参与度、英文书写和竞争力都很突出，印度开发者也已经广泛出现在国际软件企业和开源社区中。
- 印度当前更像中国在 2000 年代的阶段：产业和市场快速扩张，教育、人才选择和对新技术的参与互相推动，软件行业的发展又会进一步吸引更多人进入这个领域。

### 25:00-38:21：印度的产业转型与发展窗口

- 节目认为，印度过去长期依赖软件开发、客服和其他人力资源外包；之后以古吉拉特邦为代表的政策实践开始强调招商引资、基础设施和制造业，把服务业与制造业、高科技结合起来。
- 印度的 IT 企业也在从承接外包逐步转向互联网产品和本土业务。中国企业在印度的投资和研发活动，又会带来就业、经验积累和本地创业的连锁效应。
- 嘉宾用一位同时维护多个知名开源工具、为降低生活成本而回到印度的开发者作为例子，说明产业扩大后，足够大的开发者群体会为少数有天赋或特别投入的人提供成长空间。
- 讨论反对“硬吹”和“硬黑”两种简单叙事，认为印度的人口规模、软件人才基数、国际环境和产业增长都是真实优势，但政策连续性、基础设施和未来政治选择仍可能改变发展轨迹。

### 38:22-49:54：从开源学到知识网络

- 节目提出“开源学”的设想：开源不只是技术问题，也可以从社会学、经济学、人类学、历史和法律等角度研究，并把这些经验组织成一个跨学科知识体系。
- 嘉宾最初尝试用维基整理开源经验，但传统维基的账号和编辑方式不够适合开源协作，缺少类似代码仓库中的 Fork、Pull Request 和审核流程。
- 另一个方向是用 mdBook 写开源领域的书，并扩展 Markdown，使同一份内容可以生成书籍、幻灯片、图表、博客或课程材料。通过双向链接和段落引用，知识库与书籍之间可以形成相互连接的网络。
- 这套思路的重点不是把所有工具从零开发出来，而是利用现有开源组件，把版本管理、内容协作、结构化格式和多种展示方式组合起来。

### 49:55-59:34：协同写作、知识库与知识图谱

- 节目把知识工程区分为不同层次：首先是让更多人低门槛参与的协同写作，其次是把分散的信息整理成知识库，最后才是结构化程度更高的知识图谱。
- 大规模协同写作需要允许自由贡献，再通过编辑、审核和发布把内容稳定下来；工具的门槛越低，越容易吸引不需要学习复杂语法的参与者。
- Markdown 具备简单、易学和跨工具兼容的共同语法，适合作为协同写作的起点；但信息集合并不会自动成为知识，仍需要概念、关系和上下文的整理。
- 知识图谱的价值在于把知识实体及其关系结构化。它适合什么程度，取决于最终应用：写一本可持续更新的书，可能只需要关键词和元数据；分析、预测或智能问答则需要更严格的知识结构。

### 59:35-01:02:57：知识抽取与教育能力图谱

- 对快速发展的开源和计算机领域，先自顶向下列出全部实体和概念很难。更可行的路径是先积累维基、问答和书籍等非结构化内容，再通过标签和程序逐步发现知识。
- 知识抽取需要解决实体合并和关系识别，例如判断不同写法是否指向同一个项目，以及识别项目与语言、浏览器或其他工具之间的关系。现阶段机器学习还不能完全替代人工标注。
- 知识图谱的建设深度必须服从应用目标，不能为了“智能化”而预先建造过度复杂的架构。明确要做的是书籍、课程、统计分析还是问答系统，才能决定投入哪些结构化工作。
- 受约束的 Markdown 比完全自由的文本更容易协作、解析和抽取知识。节目把这个思路延伸到计算机通识教育：教育可以用能力图谱描述学习者当前能力、目标能力和两者之间需要补齐的差距。

### 01:02:57-01:10:11：2023 年的开源与教育计划

- 王老师计划推进中国开源领域的数据分析项目，并配套建设网站排名、插件和数据大屏等下游项目，让开源数据能够被持续观察和使用。
- 嘉宾希望从通识教育的角度推进全民计算机科学教育，让更多人学习编程和计算机思维，并在 2023 年把已有酝酿转化为具体落地的内容和方法。
- 节目本身已经连续更新近一年，嘉宾希望继续提高趣味性、听友互动和内容输出，同时尝试新的形式和主题。
- 老庄把写代码视为一种娱乐，也希望把个人为了解决问题而做的工具开源出去，让它从“自己挠痒痒”变成能够帮助其他人的公共成果。

### 01:10:12-01:16:59：个人期许与节目一周年

- 三位嘉宾都希望 2023 年能够逐步走出疫情带来的停滞和限制，同时承认有些事情不由个人决定，只能在可控范围内持续做能做的事。
- 李老师计划在计算机普及教育或通识教育方面继续投入，并恢复更稳定的写作和协作，围绕知识图谱、编程基础等主题制作面向普通人的内容。
- 节目希望继续保持更新，并在春节后的节目一周年附近组织一次听友联欢或讨论，让听众参与回顾、提问和提出改进建议。
- 年度展望没有给出宏大指标，而是落在开源项目、教育内容、协作写作、代码实践和听友交流等可以逐步推进的具体行动上。

## 核心观点

1. 数据要素真正进入流通和交易，前提不是单纯放开市场，而是先建立产权、分类、追溯、隐私和安全治理的共同基础。
2. 一个国家的开发者增长不能脱离产业阶段、人口规模和人才流动来解读；印度的增长值得重视，但不适合被压缩成简单的“超过”或“落后”结论。
3. 开源知识工程需要同时设计内容、协作方式和技术结构。低门槛贡献、版本化审核和可复用格式，是知识网络能够持续增长的基础。
4. 知识图谱不是所有项目的起点。应该先明确应用目标，再决定需要多少实体、关系、人工标注和结构化投入。
5. 长期计划更容易从具体工具和真实需求开始，再逐步抽象出架构、课程和公共协作机制；开源、教育和节目运营都需要持续反馈而不是一次性完成。
