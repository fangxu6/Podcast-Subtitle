# 第 70 期 重新上路的互联网金融与高等教育

- SRT 条目：513

## 内容摘要

本期先讨论 Meta 推出的 Threads。它借助 Instagram 的账号和关系链快速完成冷启动，短时间内吸引了大量注册用户，但能否长期与 Twitter 分庭抗礼，仍取决于内容活跃度、用户迁移和 Twitter 自身是否继续损害产品体验。节目随后谈到荷兰限制光刻机出口、中国对镓和锗实施出口管制，以及美国可能限制中国企业使用 GPU 云服务，认为芯片和算力竞争正在从军用技术管制扩展到更广泛的商业与产业竞争。

节目还分析苹果市值突破三万亿美元背后的硬件、分红和现金管理模式，并重点解读互联网金融平台整改后的巨额罚单。主播认为罚款更像是专项治理告一段落、平台重新进入常态化监管的信号；真正重要的变化是支付、征信、股权结构和算法被纳入更清晰的数据与金融治理框架。

后半段从“十年培养六十万博士”谈博士培养规模、质量、名额和工程博士，再进入大学微专业的试点。节目认为，微专业的价值在于用较短时间帮助学生进入一个跨领域能力体系，而数字素养和开源教育能否真正成立，还要通过课程质量、真实实践、师资、招生和可验证的成功案例逐步探索。

## 时间线

### 00:00-08:47：Threads 上线与社交平台迁移

- Meta 推出的 Threads 在产品形态上接近 Twitter，但准备时间较充分，且直接绑定 Instagram 的账号和关系链，降低了注册与冷启动成本。
- 上线四天后注册用户达到七千万。节目认为，即使活跃用户只有其中一部分，也足以支撑一个社交网络，因此不能简单把它看成 Clubhouse 式的短暂热点。
- Threads 能否长期发展，关键不只是自身功能，而是 Twitter 的用户活跃度会否因限流、关闭第三方 API 和缺乏正式沟通继续下降，从而形成用户迁移。
- 节目对 Threads 最终取代 Twitter 保持谨慎，但认为它与用户自行搭建的小型开放平台不同，至少已经具备争夺同一用户群的规模基础。

### 08:47-18:25：光刻机、算力限制与芯片产业自主化

- 荷兰决定从九月起对光刻机出口实施政府审批，节目认为这与美国压力和关键部件来源有关；中国随后对镓、锗等稀有金属实施出口管制，形成相互施压。
- 美国媒体所称的“禁止中国企业使用美国云服务”，后来被节目澄清为更可能针对 AI 计算云和 GPU 云服务，即试图堵住通过租用海外算力绕过高端 GPU 芯片限制的路径。
- 主播认为，限制已经从传统上针对军用技术的出口控制，扩展到民用基础设施和国家竞争，短期会带来芯片性能、能耗、手机升级和算力成本方面的牺牲。
- 节目判断，长期封锁反而会促使中国市场和研发力量加速培育本土芯片与算力产业；真正需要警惕的不是明确而持续的限制，而是反复释放“可能解除”的信号，导致企业不敢进行长期投入。

### 18:25-29:48：苹果市值、创新与分红模式

- 苹果市值在一个交易日收盘时突破三万亿美元，虽然随后短暂回落，但节目认为其凭借稳定的收入、利润和美国市场中的 iPhone 份额，仍有较强的长期支撑。
- 乔布斯更擅长创造改变产业的产品，蒂姆·库克则把供应链、运营和一个相对不依赖新故事的硬件商业模式做到了极致；不能因为缺少前者式的创新，就否认后者的经营能力。
- 苹果不依赖大规模并购扩张，而是保持高度整合的硬件生态，并通过持续分红把巨额现金交还股东。稳定的分红吸引长期持股者，也成为其市值管理的重要方式。
- 节目把苹果与华为作了有限比较：两家公司都更依赖硬件和自身能力积累，不一定适合通过投资外部公司扩张；企业应尊重自己的能力结构，不要盲目跨入不擅长的领域。

### 29:48-52:54：互联网金融整改与数据治理

- 央行等监管部门对多家线上支付和金融平台开出罚单。节目认为，媒体过度突出罚款金额，容易把一次专项整改的收尾误读为单纯打压；公告中“转入常态化监管”更像是为平台划清新边界。
- 整改要求支付业务回归本源，支付平台上的资金不能被不当挪用于高风险金融活动；用户余额可以在充分提示风险的前提下被引导购买其他产品，但支付和金融产品之间的隐性绑定需要被切断。
- 互联网平台利用电商、社交和交易积累的数据开展征信，形成了相对传统金融机构的优势。征信数据是否能被平台直接使用、是否应纳入公共征信体系，是数据治理的重要问题。
- 蚂蚁等大型平台还要按金融控股公司的标准管理股权结构、资本金和风险准备金，过去用少量资金撬动大量金融业务的模式难以继续。监管重点正从罚款转向支付、征信、股权、流动性和算法的系统治理。
- 金融算法需要具备事后可解释性：平台应说明算法为何得出某种征信、推荐或投资结果，以及结果的适用边界和风险。节目认为，这种对数据和算法的治理将成为未来金融监管的重要方向。

### 52:54-01:10:53：博士培养规模、质量与工程博士

- “过去十年培养六十万博士”听起来数量庞大，但节目先区分了拥有博士授予权的机构、具体学科授予点和真正完成培养之间的差别，认为这个数字不能脱离规模背景理解。
- 近十年拥有博士授予权的学校数量显著增加，但博士培养的时间和质量要求也更明确：学制普遍延长到四年，最长修读年限通常受到限制，论文、专利和高水平会议等要求增加了培养压力。
- 博士教育曾经允许一部分高校教师在职攻读，后来更强调全脱产以保证投入和质量；随着产业技术发展，芯片、集成电路和技术软件等领域又开始探索由工业界人员参与的工程博士培养。
- 博士招生名额仍受到严格控制，并与博士点的师资和导师数量相关。优秀博士需要长期投入，而相对于硕士毕业后的就业机会，博士阶段的收入和时间成本使招生仍然困难。
- 节目认为，好的博士并没有因为培养数量增加就变得过剩，博士教育既要承担科学研究人才培养，也要面对企业对独特技术创造能力的需求。

### 01:10:53-01:24:13：开源微专业与数字素养微专业

- 上海外经贸大学尝试开设面向商科学生的开源微专业，计划用三年完成十一门课程、二十四个学分，内容涵盖数字经济、开放式组织、开源协议、公共知识产权、平台协作、供应链、企业开源战略和社区运营。
- 节目把开源解释为一种大规模社会化协作方式，而不只是技术人员使用的软件许可证。商科、经济学、管理学、法学和社会学知识，都可以用来理解企业如何参与和运营开源生态。
- 另一项微专业名为“数字素养与计算机科学教育”，计划在一年内完成五门课程，内容包括编程思维与实践、数据思维与实践、人工智能与算法、人工智能时代的教师数字素养，以及通过授课进行实践。
- “Learning by teaching”被视为重要方法：教别人并不意味着必须成为教师，而是迫使学习者分析、解释和传授知识，从而加深自己的理解和沟通能力。
- 两个微专业的形式和周期差异很大，也说明学校仍在探索微专业究竟是短期通识补充、跨专业能力入口，还是通往正式专业的一种试点路径。

### 01:24:14-01:39:25：微专业的目标与试点难题

- 微专业的核心不是在短时间内教完一门编程语言，而是让学生进入一个能力体系。编程可以作为入口，训练探索、试错、问题分解、建立数据模型和与计算机深入沟通的能力。
- AI 时代不必把算法实现本身当成唯一目标。更重要的能力可能是分析问题、选择合适的算法，再借助工具实现并比较结果；把复杂概念讲清楚同样需要深入理解和大量真实案例。
- 学校和教育管理部门希望借微专业进行快速试点、迭代改革，并拉通不同学院的师资与课程。但学生在选择时会考虑课程是否稳定、能否持续开设、收费和学分成本，以及它对未来就业是否有明确价值。
- 招生实践说明，好的课程不一定能自然吸引学生。低年级学生可能还没有接触社会需求，也不容易理解一个尚在试验中的新能力方向；研究生和已毕业人群反而更容易意识到这类课程的价值。
- 节目认为，试点不必一开始追求大规模。只要用认真设计和完整实施做出少量成功案例，就能验证课程是否有效，再逐步扩大影响，并让数字素养教育更早进入学校和社会场景。

## 核心观点

1. 新平台的冷启动可以靠账号关系链和产品准备快速完成，但长期社交网络的生命力仍取决于活跃度、交流质量和平台治理，而不是注册数字。
2. 技术封锁会带来短期成本，却也可能促使大市场加速建立自己的硬件、软件和算力生态；产业决策需要按长期确定性安排投入。
3. 互联网金融整改的重点不只是罚款，而是让支付、征信、股权、资本和算法回到可监管的金融框架，并逐步转向数据治理。
4. 博士培养数量必须结合授予权、学科点、导师、培养周期和质量要求理解；扩招不等于优秀研究人才已经充足。
5. 微专业的价值在于用较短路径建立跨领域能力，但它必须通过真实课程、实践、师资和成功案例证明自己，而不能只靠新名词和招生宣传。
