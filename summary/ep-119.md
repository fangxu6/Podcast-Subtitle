## 内容摘要

本期先跟进江平数学竞赛事件。新的板书疑点、学校月考成绩和各方公开信让节目认为事件中确实存在需要解释的矛盾，但作弊指控、性别立场和专业圈站队都不能替代证据。节目把主要责任放在掌握完整资料、却又主动宣传排名和拍摄视频的比赛主办方身上，并讨论了媒体如何把一个竞赛事件加工成“造神—质疑—反转”的流量故事。

随后节目预告华为仓颉编程语言，关注它把多种语言特性和面向大模型的能力缝合在一起的做法，也提醒新语言必须找到独特场景、保持语义一致并建立良好的社区沟通。大模型部分则介绍通义千问 2、DeepSeek-Coder V2 等国产模型的进步，讨论基座模型进入平台期后，模型评测如何变得更细，以及泛化能力和行业应用之间的平衡。

节目的主要篇幅讨论拜登与特朗普的首次电视辩论：电视辩论更像争取摇摆选民的形象竞争，而不是完整比较治国能力；拜登没有证明自己仍然适合连任，特朗普则以清晰表达掩盖大量事实错误。最后，节目分析上海卫生健康信息化白皮书中的“涉 A 组件”概念，主张按闭源、单一厂商控制、国际基金会治理等层次区分技术风险，而不是把所有与美国有关的开源软件放在同一等级。

## 时间线

### 00:00-15:50：江平事件的新证据与责任归属

- 节目跟进上期讨论的江平数学竞赛事件。当地教育局的回应、江平中专学校一次 83 分的数学月考成绩，以及阿里宣传视频中的板书疑点，都让预赛成绩与既有信息之间出现难以忽略的矛盾。
- 北京大学数学家袁新意整理了板书中的多处问题，包括江平亲手书写的公式也存在疑点。节目认为这些问题需要解释，但也指出袁新意的导师与比赛组委会有关系，因此他在表述上可能需要顾及影响。
- 豆瓣上出现参赛者公开信质疑成绩，但部分署名只写学校甚至完全不署名。节目认为，质疑本身可以成立，匿名或模糊署名却削弱了质疑者承担责任和接受检验的意愿。
- 另一篇以女权话语支持江平的文章，正确指出被质疑者没有义务自证其罪，却把所有质疑都归为父权体系下的围剿。节目反对把有证据的专业分析、无端造谣和性别对立混为一谈。
- 无论江平最终真实水平如何，比赛主办方都比学生、老师和教育局更有条件掌握原始数据，也更有责任解释成绩、板书和宣传视频之间的关系。

### 15:50-28:46：华为仓颉与新编程语言的取舍

- 华为开发者大会公布了鸿蒙原生版本的更多细节，并推出仓颉编程语言。节目当时尚未亲自使用，试用需要申请开发者资格，已有反馈还包括不稳定和细节问题，因此只作初步介绍。
- 仓颉的第一印象是“缝合怪”：它吸收了多种语言中被认为有价值的特性，同时加入面向大模型对接的语言设计。节目认可后一个方向，但认为最终效果还要看它能否支持盘古之外的平台和模型。
- 语言特性并非越多越好。语法越灵活、表达力越强，学习成本和团队协作中的规范控制也可能越高；设计者需要说明这些特性解决了什么实际问题。
- 新语言至少要具备一种明确优势：在某个场景中明显胜过其他语言，或能有效替代一个已有语言。节目以 Swift 为例，指出它虽有许多好特性，却主要被苹果生态内部使用，缺少更广泛的独特场景。
- 仓颉的函数处理曾引发讨论：函数名在没有括号时如何解释、函数是否是一等对象、遇到未覆盖的情形应该返回对象还是报错。节目据此担心语言设计可能尚未打磨成熟。
- 除了语言本身，团队与社区沟通也很重要。开发者反馈不应被设计者直接当作对个人方案的攻击，项目最好由专门人员负责开发者关系，而不是临时让工程师去充当客服。

### 28:46-38:26：苏州刺伤事件与恶意叙事

- 节目讨论苏州一名女性在阻止刺伤日本人的行凶者时重伤并去世的事件，认为对她的英勇行为进行报道、纪念和表彰都是应当的。
- 早期报道只突出“两名日本人受伤”，后续又出现把事件解释成中国民粹、排外或仇日的材料；节目认为两种报道都可能利用案件服务于自己的叙事，而不是完整呈现事实。
- 节目反对把这位女性描述成“替仇恨教育牺牲”或“挽救外交危机”的符号，也反对用个别网络仇恨言论概括中国社会。截图和转述应同时保留相关评论的上下文，不能只截取有利于论证的一部分。
- 关于日本企业因事件集体撤离苏州的网传截图，节目认为企业决策不可能如此迅速，相关说法缺少可信依据。面对可能造成现实伤害的传播，应先查证来源和时间，再讨论影响。
- 节目提醒，境内外不同立场的人都可能把极端言论当作宣传素材；真正需要警惕的是恶意叙事和断章取义，而不是把所有普通人归入同一种立场。

### 38:26-50:26：国产大模型、基准测试与应用落地

- 节目判断，2024 年上半年大模型基座能力仍在稳步提升，但暂时缺少上一阶段那种耀眼的跳跃式突破；经过一年多追赶，国内模型已经形成更有竞争力的第一梯队。
- Hugging Face 重新组织了主流模型的系统评测，通义千问 2 的较高版本在当时的基准测试中取得领先。它以开源形式提供了除 Llama 之外的选择，也为后续定制和本地部署留下空间。
- DeepSeek-Coder V2 被介绍为面向编程和数学推理优化的模型，完整版本超过 100GB，运行它可能需要 128GB 显存；节目对其能力的评价主要来自社区反馈，因为当时没有亲自测试。
- 模型能力逐渐接近后，基准测试也进入瓶颈：不同模型的得分差距变小，测试结果变得“平”。评测者希望提高测量精度，或把通用能力拆成数学、编程、教育等更细的专项。
- 过度拆分又可能让模型为了某一项测试过拟合，牺牲通用性。理想的评测既要看细分能力，也要保留对泛化能力的衡量。
- 国内厂商开始寻找教育、学习机和其他行业场景，把模型从“有想象空间”变成稳定、可靠、可以放心使用的产品；节目认为产品化最后一步往往比展示模型能力更难。

### 50:26-01:00:21：电视辩论的媒介逻辑与高尔夫插曲

- 节目从 1960 年肯尼迪与尼克松的首次电视辩论谈起：当年电视观众超过 7000 万，观看画面的人普遍更支持形象放松、年轻有活力的肯尼迪，而只听广播的人对尼克松评价更高。
- 电视辩论的特殊影响来自视觉形象。到了网络时代，候选人可以通过长期内容和社交媒体反复展示自己，电视辩论不再是唯一的形象窗口，只是漫长选战中的一个回合。
- 总统辩论的核心目标不是说服对手，也不是在有限时间内完整证明谁更会治理国家，而是争取摇摆选民。一次辩论只有约一个半小时，却要快速覆盖近二十个主题，因此很难展开真正深入的政策说明。
- 这次辩论设置了回答时限和关闭麦克风等规则，表面上是限制特朗普打断对手，实际也让双方更多回避问题、攻击对方和展示个人状态。
- 辩论中出现了年龄、道德、战争和身材等相互攻击，最受传播的是两位候选人围绕高尔夫水平的争执。节目认为这些梗适合二次创作，却不能代表总统能力的完整比较。

### 01:00:21-01:10:36：经济议题、事实错误与候选人形象

- 美国大选中的核心仍是国内经济和社会问题，本次辩论集中在通货膨胀、移民、堕胎和芬太尼等议题；国际事务虽然重要，却未必是普通选民最直接的判断依据。
- 现任总统通常需要强调自己的政绩，并提醒选民前任留下的困难。拜登本可以借 2022 年《降低通胀法案》、医保药价上限和缴费限制等内容说明政策收益，但现场没有清晰完成这次回应。
- 拜登试图用失业率攻击特朗普，却把特朗普上任时的失业率与新冠疫情期间超过 15% 的失业率混淆；他还把 1500 万个新增工作岗位说成 1.5 万个，把 billionaire 说成 trillionaire。
- 特朗普表达清楚、反应迅速，但也毫不迟疑地说出大量事实错误。辩论后的事实核查认为两边都有问题，只是公众对特朗普一贯夸张和失实的说法已经更加习惯。
- 节目认为，特朗普这次更像是在证明自己仍然“正常”，拜登则主要想证明自己还不老、能够再干四年；辩论因而变成两个人的状态展示，而不是政策能力考试。

### 01:10:36-01:20:17：拜登的年龄困境与辩论后的民调

- 拜登嗓音嘶哑、表达含糊，并多次卡顿，连不少美国媒体和观众都认为难以听清。主持人专门给了他解释年龄和健康问题的机会，但他没有有效回答，辩论结束后被夫人搀扶下台的画面又强化了这种担忧。
- 节目用 1984 年里根回应年龄质疑的方式作对比：里根把经验和反应能力转化成优势，而拜登没有在现场把年龄转化为可信的政治叙事。
- CNN 的即时调查中，认为特朗普赢得辩论的观众约为 67%，认为拜登赢的约为 33%；与四年前拜登在辩论民调中的表现相比，这次明显滑坡。
- 其他关于两人领导能力的调查变化较小，但拜登获得“非常有信心”的比例显著低于特朗普。节目据此认为，辩论对拜登在年龄和健康问题上的失分尤其严重。
- 拜登次日承认自己年纪大、腿脚和口齿不如从前，但强调自己诚实，并表示退选不在考虑范围内。节目认为这段解释若在辩论现场说出，可能比事后补充更有效。

### 01:20:17-01:30:07：候选人更换、党派立场与投票率

- 拜登团队主动把通常在党代会之后举行的辩论提前到六月，节目推测原因可能是预见到风险，或希望尽早暴露问题以争取补救时间；关于是否借此准备更换候选人，节目明确把它作为政治推测。
- 民主党在流程上存在更换候选人的工具，但真正执行会遇到党内年轻候选人不愿承担挑战现任总统的道义压力、缺少公认替代人选等困难。拜登本人也公开表示不会退选。
- 节目认为，辩论对特朗普是有得有失，对拜登则更不利；它可能让一部分中间选民更加厌倦两位候选人，降低投票意愿，而特朗普的铁杆支持者仍然更坚定。
- 另一位主播质疑美国总统制过度依赖个人英雄式表现：总统应当与智囊团和行政团队协作，电视上即时、幽默地回答问题不应成为判断国家领导能力的主要标准。
- 选民实际还会根据税收、堕胎、环保、能源等持续性的政策立场选择政党，而这些议题在短促的辩论形式中很难充分展开。

### 01:30:07-01:40:04：上海卫生健康白皮书与“涉 A 组件”

- 上海卫生健康领域的信息技术应用创新白皮书，可能影响公立医院及相关全民健康信息平台使用哪些技术组件。节目重点澄清其中的“涉 A”不是字母等级，而是“涉及美国”的意思。
- 节目认为，报道者把原文架构图和“红色为涉 A 组件，需要替换”等说明读错，直接写成 C#/.NET 被认定为某种 A 组件，导致标题和后续讨论失焦。
- C#/.NET 已经开源、跨平台，并以基金会和社区方式运作，但节目指出这不等于它完全脱离微软主导。判断风险时应区分“是否开源”和“是否由单一美国厂商控制”。
- 最硬的一层风险是 Oracle、Windows Server 等美国公司控制的闭源软件：即使厂商愿意销售，也可能受到出口管制影响。第二层是开源但由单一厂商控制的软件，未来可能改变许可证、闭源、停止对华提供服务或转向限制商业使用的协议。
- 把所有放在 GitHub 上的软件都称为涉 A，或把捐给 Linux、Apache 等国际基金会的项目与闭源美国软件视为同等风险，都是过度简化。基金会治理降低了单一企业控制风险，但不代表绝对安全。
- 节目认为，C#/.NET 是否需要替换不能只凭政治标签决定，应看它的实际控制关系、许可证、供应链、替代成本和业务重要性。

### 01:40:04-01:44:02：风险分层与可执行标准

- 节目不否认美国出口管制、GitHub 访问受限和单一厂商改变政策等风险，但认为这些风险必须分层，不能把 .NET、Apache、Nginx 和 Windows Server 视为同一级别。
- 对真正高风险的闭源美国软件，应提前准备替代方案；对国际开源项目，即使未来无法直接访问，也可以通过镜像、分叉和已有代码继续使用，因此风险表现不同。
- 比较难判断的是处于中间层的、开源但仍由单一美国公司主导的项目。它既不能被简单宣布为安全，也不应直接等同于最严重的闭源软件风险。
- “涉 A”标准需要由相关部门、企业和专业专家共同制定，并明确证据、处置方式、审查周期和迭代机制；如果各地各自划线，容易被利益、宣传或专业误读影响。
- 节目最后强调，标准的价值不在于口号是否绝对正确，而在于是否专业、可执行，并能随着技术和国际环境变化定期复核。

## 核心观点

1. 对竞赛成绩、网络事件和政治争议的判断，都应把原始证据、责任主体和不确定性分开，不能用站队或反转叙事替代事实核查。
2. 新编程语言的价值不在于堆积多少先进语法，而在于能否解决明确问题、形成独特场景、保持设计一致并长期经营开发者社区。
3. 大模型基座能力趋于接近后，模型评测需要在专项能力和泛化能力之间保持平衡，真正的竞争会逐渐转向可靠的行业产品化。
4. 电视辩论擅长展示候选人的形象和状态，却不适合在短时间内完整比较治理能力；选民仍需回到长期政策、事实记录和团队能力。
5. 技术自主和供应链安全不能靠简单标签完成。开源程度、控制者、许可证、替代成本和业务重要性共同决定风险，标准也必须由专业力量持续复核。
