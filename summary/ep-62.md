# 第 62 期 智能家居和开会难

- 来源：`transcript-site/episodes/ep-62.html`

- SRT 条目：726
- 阅读段落：121

## 内容摘要

本期先从 OPPO 解散自研芯片团队谈起，分析手机芯片设计为什么不能只看设计能力，还要依赖制造、设备、材料、产量和长期供应链协作。节目认为，手机市场已经接近饱和，换机频率下降，厂商需要寻找新的增长点；通用 GPU 和汽车等方向可能比继续追逐手机芯片更有现实机会。

随后节目讨论开源世界的尴尬时刻：高使用量的 npm 包往往由个人无偿维护，维护者疲倦、转让项目或删除依赖，都可能引发供应链事故，但项目影响力并不自动等于维护者收入。节目还以一套极客自建的智能家居系统为例，讨论传感器、局域网、远程访问、隐私和实际场景，认为当前智能家居更像爱好者的工程玩具，真正面向普通人的产品必须降低安装和维护难度，并从明确的刚需出发。

最后集中讨论如何开好会。无目标、无准备、领导借会议减压或不尊重参与者的会议，即使套上“头脑风暴”的名字也很难产生结果。有效会议需要先明确目的，再匹配征求意见、决策宣讲、工作跟踪等不同形式，并通过会前材料、主持、时间控制、规范纪要和 TODO 跟进形成闭环；线上会议在多数需要理性协作的场景中并不比线下低效。

## 时间线

### 00:00-10:16：OPPO 自研芯片团队与制造产业链

- OPPO 的自研芯片团队于 2019 年成立，经过三年多后解散，期间没有公开发布具有明显影响力的芯片成果，节目认为这种无疾而终值得追问立项和资源规划是否充分。
- 芯片设计只是产业链中靠下游的一环，设计完成后还要依赖晶圆制造、光刻设备、光刻胶和其他材料；先进工艺需要设计方与制造方反复协作，并不是标准化工厂可以直接接单生产。
- 苹果等稳定的大客户能够让台积电及其上游投入资源共同优化工艺，而出货量小、仍在摸索的新团队很难获得同等支持，芯片产业因此具有明显的马太效应。
- 芯片设计团队如果没有足够的产品规模和产业政策支持，可能既无法摊薄研发成本，也难以让制造环节愿意配合；不能把“能设计”直接等同于“能做成并量产”。

### 10:16-17:00：OPPO 的企业基因与高端芯片挑战

- 节目认为，OPPO 和 vivo 都源自步步高体系，其优势长期在于紧跟技术潮流、品牌建设和销售渠道，而不是从一开始就积累战略级芯片研发能力。
- 华为在高端手机上通过麒麟和海思形成了较强的芯片、系统和产品整合能力；OPPO 试图向高端市场和芯片方向靠拢，可能带有跟随成功路径的惯性，但企业能力结构并不完全相同。
- 手机软件、定制 Android 系统和消费电子硬件整合，和高端芯片设计及其产业链协作不是同一种研发难度；成熟的消费电子经验不能自动迁移到芯片产业。
- 芯片项目在立项时需要预估周期、投入、产出和最坏情况。若既没有明确产品，也没有阶段性成果和退出判断，数百人的资源投入就可能变成难以解释的浪费。

### 17:00-22:51：GPGPU 与智能手机增长放缓

- 节目认为，若国内企业只能做芯片设计而不能控制制造，手机芯片会受到先进制程、体积和能耗要求的限制；五到七纳米等制程是否能追上，需要时间和产业积累。
- 面向通用计算的 GPU 可能是更现实的方向。腾讯、字节跳动等企业需要 AI 算力，GPGPU 在制程要求和应用需求上，可能比手机 SoC 更适合成为自研芯片的切入口。
- 智能手机的硬件性能已经足够，主播分享自己多年不换手机的经历，认为用户换机频率下降，单纯提高速度或改变外观已很难制造过去那种强烈的升级动力。
- 手机市场的持有量接近饱和，厂商需要寻找新的增长点；汽车被节目视为正在形成的亮点，华为较早进入这一方向可能获得新的机会。

### 22:51-34:24：开源维护者与 npm 供应链事故

- 节目介绍一篇总结开源项目困境的文章：有维护者因为疲惫把项目转交他人，接手者却在包中埋入窃取数字货币的后门，原维护者是否应承担责任至今并没有清晰结论。
- 另一个案例中，npm 维护者因与官方发生矛盾删除自己维护的数百个模块，其中被大量项目依赖的 `left-pad` 让许多网站和服务器受到影响，暴露出依赖链过于脆弱的问题。
- 多位 JavaScript 包维护者的项目每周有数千乃至数千万次下载，但个人生活仍然窘迫；开源项目的使用量、社会影响和维护者收入之间没有自然的正相关关系。
- 开源依赖可以由个人随时维护、转让或删除，而上游包又可能被下游大量嵌套使用。节目认为，供应链工具和平台机制应更认真地处理依赖所有权、版本锁定与安全责任。

### 34:24-41:57：开源的价值与经济回报

- 包被很多人使用，并不代表它本身具有不可替代的价值；如果别人可以很快写出同样甚至更好的替代品，原项目的用户数量就不能直接决定其商业价值。
- 维护者如果打算从开源项目赚钱，应在开放之前就想好收入路径。项目完全开放后再试图收回权利或迫使用户付费，通常会面临很高的迁移成本和信任成本。
- 很多个人开源项目更接近公益事业。相对可行的收入来源可能是大厂的战略投资、基础设施项目的基金会运作，或通过项目声誉帮助维护者获得工作机会，但成功概率并不高。
- “礼物文化”只描述了开源社区中可见的成功故事。海平面以下还有大量不出名的贡献者和没有投资价值、却很重要的项目，不能把少数明星维护者和风投项目当成整体现实。

### 41:57-50:56：极客智能家居与隐私

- 一位极客在家中搭建了完整的智能家居系统：浏览器仪表盘可以查看温度历史、摄像头、红外传感器，以及由数百个传感器、控制器和开关组成的家庭网络。
- 系统可以远程打开空调，根据温度变化逐步调节到较稳定的状态；夜间起身时，传感器可以自动开灯，但人在原地不动时红外传感器可能误判无人，需要更准确的占用检测设备。
- 自建系统可以避免把摄像头和家庭数据交给服务商，但也要求用户配置局域网、服务器、远程访问和硬件，普通人很难承担这种安装与维护成本。
- 远程监控老人、孩子、宠物和空置住宅已经有明确需求，但便利性与隐私之间存在交换：使用厂商云服务较容易，却意味着家庭信息进入服务商体系。

### 50:56-55:01：智能家居的场景与产品化

- 面向普通用户的智能家居安装难度最多应接近按照说明书组装家具；如果需要自己焊接、布线、搭服务器和处理网络访问，就很难成为大众产品。
- 真正有价值的场景往往发生在人不在家时，例如宠物自动喂食喂水、植物浇水、养鱼和远程查看家中情况；人在家时，许多自动化只是把手动操作提前或替换掉。
- 智能家居受住宅布线、Wi-Fi 覆盖、水电管线和地区房屋条件影响，旧房改造尤其困难，很多设备并不是买来就能即插即用。
- 节目认为，行业目前仍有“玩数码”的成分，缺少足够疼痛的刚需。产品能否发展起来，取决于厂商是否找到清晰场景、解决隐私和基础设施问题，而不是堆积更多联网设备。

### 55:01-01:05:46：失败的头脑风暴与会议失控

- 主播回忆一种最煎熬的会议：领导临时召集十几二十人加班，称要“头脑风暴”，却没有说明问题背景、规则或预期成果，只是逐一点名要求大家发言。
- 当参与者指出问题尚未成熟、需要先分析条件时，领导把不同意见理解成“你们都比我懂”，会议转为情绪爆发；之后大家为了尽快离开，被迫拼出一份形式完整但未必解决问题的报告。
- 规范的头脑风暴应当允许发散，不急于当场得出结论，最好由中立主持人组织、分组收集想法、抹平身份差异，再通过整理和筛选形成可执行结果。
- 学术活动和 panel 也常因主持人不敢控制专家发言时间而失控。节目以一次嘉宾因时间安排失当摔话筒的事件说明，主持、预案和时间信号是会议质量的一部分。

### 01:05:46-01:15:38：会议目的、参与者与基本方法

- 会议技巧本身并不难，真正困难的是发起者没有想清楚会议目的，或者把会议当成自己释放压力、获得心理安定的工具。
- 征求意见和头脑风暴需要平等、开放的环境，领导最好不直接主持；决策宣讲需要提前准备材料并安排问答；工作例会则应围绕事项跟踪，由项目负责人持续推进。
- 会议发起人如果不尊重参与者的时间，临时在下班后召集会议、不给准备材料或让大家空等，参与者自然会带着情绪参加，会议即使有正确目标也很难成功。
- 对大型问题，领导应先通过小范围或一对一讨论建立基本判断，再逐步扩大参与范围；不能期待一次大会议替代决策、分析和责任承担。

### 01:15:38-01:23:23：线上会议与可执行的会议闭环

- 线上会议在多数以材料、逻辑和任务协作为主的场景中并不天然低效。只要参与者适应远程协作，很多面对面才能完成的假设并不成立。
- 一些依赖表情、肢体和情绪感染的沟通适合线下，但对需要理性讨论的工作，提前发文档甚至可以替代一部分会议；只有文档难以解释的内容才需要开短会。
- 节目认可的会议实践包括会前发送议题或 PPT、提前确认参会人、指定记录人、按固定格式记录讨论事项和结论，并在会后列出 TODO 和后续负责人。
- 会议不应无限延长。若预估内容超过约四十五分钟，应拆分会议或重新组织问题；时间控制既是效率要求，也是对参与者的尊重。
- 开源社区的线上会议还可以使用协作文档和自愿参与机制，让成员先分享近况再进入议题，减少“只有头像”的疏离感，同时保留会议记录。

## 核心观点

1. 复杂产业的竞争不只是单点技术竞争。芯片设计、制造、设备、材料、产量、供应链和真实产品需求必须形成闭环，单独成立研发团队并不等于具备量产能力。
2. 开源项目的社会影响和维护者的经济回报并不自动匹配。依赖链越长，越需要明确所有权、版本、安全责任和可持续维护机制。
3. 智能家居的关键不是联网设备数量，而是普通用户能否低成本安装、稳定使用，并在隐私、远程访问和真实刚需之间取得平衡。
4. 会议失败通常先是目的失败，再表现为主持、流程或表达失败。先定义会议要解决的问题，再选择头脑风暴、宣讲或工作跟踪等形式。
5. 有效协作需要把讨论转化为闭环：会前准备、会中记录和时间控制、会后明确结论与 TODO。线上或线下只是手段，不能替代这些基本工作。
